ForesightNine 网页版完整使用与运行流程说明
版本：2026-09-13

一、项目用途与边界
ForesightNine 用于把投资观点整理成可复核的研究流程：先明确观点与时间边界，再进行反方审查、证据登记、世界线构建、概率评估、因子计算与配置方案比较。系统不连接券商、不下单、不托管资金，也不把情景结果表述为收益承诺或投资建议。

二、进入系统与账户
1. 打开 https://app.foresightnine.com。foresightnine.com 与 www.foresightnine.com 会保留路径和查询参数后跳转到该正式应用入口。
2. 匿名状态可以填写观点和查看公开方法；浏览器会在本机保存未提交草稿。
3. 使用 Google 或 GitHub 登录后，服务端写入会话，页面会重新读取账户、会员、额度与个人金融数据源配置。刷新页面后会话仍由服务端校验；退出登录后账户接口不再可用。
4. OAuth 完成页只负责交换一次性登录 ticket，不长期保存 provider authorization code。

三、API / 金融数据源配置
1. 进入左侧“控制台”，找到“API / 金融数据配置”。该区域只有登录后才显示可编辑表单。
2. 当前支持 Market Data、Alpha Vantage、Twelve Data、Finnhub 与 Yahoo Finance。前四项可以填写用户从对应供应商账户取得的 API Key；Yahoo Finance 不需要用户 Key。
3. 勾选“启用”决定该来源是否参与请求；拖动卡片或使用上下箭头调整 fallback 优先级。默认顺序为 Market Data → Alpha Vantage → Twelve Data → Finnhub → Yahoo Finance。
4. 获取 Key：Market Data 登录 Dashboard 后复制 API token（官方认证说明：https://www.marketdata.app/docs/sdk/php/authentication）；Alpha Vantage 在 https://www.alphavantage.co/support/#api-key 申请并保存 Key；Twelve Data 登录 Dashboard 后进入 API keys / security 区域复制 Key（文档：https://twelvedata.com/docs）；Finnhub 登录 https://finnhub.io/dashboard 后复制 API Token；Yahoo Finance 在本链路中不要求个人 Key。请先确认供应商套餐、调用频率、资产覆盖和数据再分发条款适合你的用途。
5. 填写新 Key 后选择“保存并测试”，系统先保存配置，再用该来源读取一个受限测试资产。显示“可用”表示标准化后的测试数据通过；显示“暂不可用”时不会伪造成功结果。
6. 输入框留空会保留已经保存的 Key；选择“移除 Key”并保存才会清除。页面只显示固定四位掩码提示：常规字母数字后缀显示末四位，其他后缀显示不可逆摘要；页面无法读取密钥原文。
7. 个人 Key 会优先覆盖同一 provider 的平台凭据；该 provider 失败后，系统按用户排序继续 fallback。使用个人 Key 不会把密钥发送给其他 provider。
8. 所有来源使用固定服务端适配器和固定 HTTPS 端点。用户不能填写任意 URL，从而降低内网访问、重定向和云 metadata 请求风险。
9. 点击页面顶部“保存 API / 数据源”可一次保存启停状态、排序和新增 Key。保存失败时原配置保持不变。

四、个人模型配置（BYOK）
1. 登录后在“控制台”的“API / 模型配置”中选择“平台模型”或“我的模型（BYOK）”。平台模型使用服务端平台路由；选择个人模型时必须填写公开 HTTPS OpenAI-compatible Base URL、模型名和 password Key。
2. 点击“保存 / 替换”会调用 PUT /v1/account/model-config；留空 Key 表示保留已保存的 Key，填写新 Key 表示替换。点击“删除我的模型”会调用 DELETE 并切回平台模型；点击“保存并测试”会先保存，再调用 POST /v1/account/model-config/test。
3. 读取接口只返回 schema_version v1、mode、configured、Base URL、模型名、updated_at 和严格的固定提示“••••XXXX”；常规字母数字后缀使用末四位，其他后缀使用不可逆摘要；页面不会回显或再次读取 Key 原文。
4. BYOK 模型请求不扣平台额度；个人模型调用失败时显示明确失败状态，不回退到平台模型，也不把失败伪装为成功。模型 Key 不进入 localStorage、日志、研究记录或任何导出文件。

五、一次研究的完整流程
1. 新建推演：填写观点、可投资资金和基础货币。观点应包含前提、时间范围、可观察触发条件以及预计的资产传导路径。
2. 反方审查：提交观点后，服务端生成结构化质疑、待补证据、问题清单和评分项。请求过程中可以取消；失败后可以重试或恢复已有结果，避免重复调用。
3. 证据确认：登记来源标题、发布者、链接、时间、摘要和用户备注，并标记证据等级及支持/反对方向。系统保留来源与内容哈希，模型推断不得冒充外部事实。
4. 世界线：确认观点后生成弱、中、强三条分支。每条分支包含事件节点、揭示日期、资产影响和失效条件。
5. 概率：P(H) 表示前提成立概率，P(W|H) 表示前提成立时世界线发生概率，联合概率按 P(H∩W)=P(H)×P(W|H) 计算。概率是可修订判断，不是客观事实。
6. 配置方案：金融数据通过校验后进入本地 FM 计算。系统同时保留 FM Raw 实验层和叠加集中度、流动性、冲击及可实施性约束的 Public Default 层。
7. 组合路径：查看不同世界线下的配置与 NAV 路径。历史数据、模型推断与模拟区间保持不同标记。

六、金融数据请求如何运行
1. 网页向同源 /snapshots 提交资产列表、截止时间、时区和三个锚点：年初、最近月初、最近已完成交易日。
2. 服务端读取当前账户的启停状态、fallback 顺序和加密凭据，然后逐个调用已准入 provider。成功来源会终止该资产本轮优先链；失败、限流或缺失会进入下一来源。
3. 返回行必须经过资产映射、日期边界、正价格、future/stale/missing、币种和响应结构校验。缺失数据保留为 missing，不使用 fixture 冒充实时数据。
4. 合格结果进入带命名空间的 Redis 缓存；个人凭据的缓存命名空间使用不可逆摘要分区，不包含 Key 原文。
5. 页面验证 market-snapshot-bundle/v1 完整性后，才更新最新价格并计算 momentum、momentum_month、rsi14、sma_ratio 等可用字段。数据不足时保持 limited_data，相关公开配置不会假装完整。
6. 当前多供应商行情链属于已授权的 staging/evaluation 运行模式；生产环境会保持关闭并返回明确警告，直到数据许可、发布审批和生产准入全部完成。正式网页入口并不等于行情供应商已经获得生产准入。

七、证据与搜索
证据搜索和资产行情搜索是两条独立链路。搜索结果只是待核验证据；用户应打开来源、核对发布日期和原文后再引用。搜索不可用时可以手工添加证据，系统不会生成虚假的替代搜索结果。A/B 级通常要求可公开复核的原始或可靠二手来源；D/E 级必须保持私有经验或模型推断标签。

八、导出文件
1. 研究 JSON：包含观点、挑战、证据、世界线、概率、配置及审计字段，是最完整的可复核记录。
2. 配置 CSV：仅包含 allocation 快照，适合表格查看，不替代完整研究记录。
3. 世界线路径 JSON：包含 premise、节点、NAV 数组与历史/模拟边界。
4. 本说明文件：用于离线查看项目操作步骤；文件不包含账户 token、Cookie、API Key 或 provider 原始凭据。

九、会员、额度与用户自有 Key
账户区域显示服务端确认的会员来源、有效期和额度。平台模型调用按服务端记录的实际 token 用量结算；重复请求应使用幂等标识避免重复计费。BYOK 模型调用不扣平台额度，个人模型失败不回退平台模型。金融数据 provider Key、模型 Key 与平台 token 额度是不同配置：填写任一个人 Key 都不会改变平台模型会员状态。

十、常见状态与处理
1. “正在确认服务端登录状态”：等待 readiness 和 session 检查完成后再操作。
2. “配置请求失败”：保留原设置，检查登录是否过期、网络是否可用，然后重新读取或保存。
3. provider“暂不可用”：检查 Key 是否有效、套餐权限、调用频率和目标资产覆盖；其余已启用来源仍会参与 fallback。
4. 数据显示 missing/limited：检查截止日期、交易日、资产映射、FX 和 provider 覆盖；不要把缺失值手工改成当前值。
5. 研究请求超时或取消：优先恢复已有 challenge/session，再决定是否重试，避免重复模型调用。
6. 页面刷新：观点草稿从当前设备恢复；账户配置和会员状态从服务端重新获取。

十一、安全与隐私
金融数据 Key 与个人模型 Key 都通过 TLS 发送到 ForesightNine 服务端，并使用彼此独立的账户绑定 AES-GCM 认证加密密钥保存。读取接口只返回是否已配置和严格掩码提示；密钥不写入 localStorage、研究导出、客户端 bundle、Git 或正常日志。账户删除会同步删除相关金融数据与模型配置。请不要把 API Key 写进观点、证据、截图或导出文件。

十二、完成前检查
确认登录状态正确；确认数据来源启停和顺序已保存；逐个测试新增 Key；确认三个锚点及 FX 状态；核对每条证据原文；阅读世界线失效条件；区分 FM Raw 与 Public Default；导出完整 JSON 留档；把所有结果视为研究材料而不是交易指令。
