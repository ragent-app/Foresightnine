## 二、按依赖顺序实施

### 阶段 1　建立能区分召回、选段与推理的对照

评估负责人冻结代码、原文版本、发布和研究时点、许可、问题、段数和字节上限。将已公开答案的 S、H、J 转为开发及回归材料。另按发行主体、事件和原始文档家族隔离一批中英文新题，保留同稿、单文即可回答、两文互补、重要反证、口径冲突与真正缺源的情况。先写明每个核心分项的等价证据组、必须保留的限制、应撤回的主张及评分规则，冻结后才运行候选版。运行时只收到研究输入。

针对同一题保留四条记录：①许可语料中理论可装入的最好组合；②**实际候选池**中可装入的最好组合；③工具选中且实际进入请求的组合；④可重开版本中的答案及其依赖。前两项由离线评估器用答案标注计算，产品代码不读取标注。若②低于①，优先修查找；③低于②，修选择或请求构造；③完整而④错误，用相同已读证据重放计算与提交。**交付**一张逐题失分表，注明首次损失、是否可得、容量和实际入模位置。它是调策略前的验收件。

### 阶段 2　把需求变成可检索的证据组合，再做有限容量选择

研究后端扩展既有 `requirement_id` 和引用关系。每项需求记录所需材料的用途、可替代材料、需要共同出现的要素、限制或反证，以及兼容条件。以三类需求起步：跨期变化需要同主体同口径的两期指标；变化归因还需要直接说明该变化的披露；合同条件和同期比较分别需要完整条件链、两个标的的同窗口数值。一个段落可以同时满足多个用途，单一事实题允许一份原始披露完成。需求与候选的匹配保持“待核”直至实际阅读。[需求评估](../../apps/api/app/research_evidence_requirements.py) · [现有分项契约](../../apps/api/app/research_topics.py)

1. **保留主查询。** 将原题召回与缺项查询合并。先查已有事实及获准本地资料，利用已读原文里的指标名、条款号或附注号定向补查。资料不在库且有授权时再按用途路由至发行人披露、合同原件或行情连接器；显式空来源、仅获准搜索线索、禁用 FRED 等边界照旧。分别记录未召回、取得失败、权限不符和已读仍无披露。
2. **在候选池内比较组合。** 第一版直接对两段容量比较单段和段对。先排除越权、时点不符及已知主体/期间/币种冲突的组合；对其余组合优先保留能覆盖完整核心需求、给出关键例外或反向材料的片段，再比较定位质量、重复和总字节。提取签名以实际原文区间为准，重叠区间只计一次。完全相同的稿件复用；仅部分相似的转载仍保留新增披露，独家原始报道可独立入选。已有数字的摘要不能代表原表及附注都已读。
3. **把计算成本限制在检索内部。** 先为每个用途保留少量有定位的候选及必要反证，再做有界组合比较。超过两段时使用固定宽度搜索，保留当前组合、可替换位置和未满足需求；在小池用穷举检查近似算法损失。报告裁掉必要候选的次数。已有压力样本最多约千个合并候选，不能把全池任意组合枚举放到每一轮。记录有、无性能分析器的时间和峰值内存。[既有成本审计](context-evidence-acceptance/selection/versions/audit/README.md)
4. **单独验证补查。** 先固定查询、候选池和字节，只换选择器；再固定选择器与查询次数，只换缺项查询。尚欠一端时只向协调 Agent 返回缺哪端、可展开位置及下一次查询。无新增授权材料或明确预算已尽时，交付现有分项与缺口。512 字节是本次实验对照条件；产品仍按协议窗口和用户实际设置运行。

**出口**：J1–J3 的开发回放要能找回先前漏掉的价格披露、撤单条件和股票行情，J4 保留“处置贡献未披露”。新留存题另报逐题改善、持平、退化。若改善只出现在旧题，保留实验结果，继续查泛化原因。

### 阶段 3　从“原文出现”到“结论成立”

- **财报及 PDF。** 已有 PDF 回放能取到两页表格，但年份被拆行后列期间仍未知。读取器应保留页码、文字框位置与阅读顺序，用表头区域关联日期、币种、倍率、列和续页；附注号另连到实际读到的正文及版本。并列标题、表头反转、OCR 歧义或附注重号不能唯一消解时，返回候选页与部分结果，保留可确认的行。用合法留存的真实发行人 PDF 和现有自编 PDF 做整表到引用回放，分别报告列期间解析率、错误绑定数和正确弃答数。[现有 PDF 回放](context-evidence-acceptance/evidence/pdf-replay.json) · [财报提取](../../apps/api/app/research_statement_extraction.py)
- **行情与合同。** 行情由确定性工具按标的、币种、价格口径和实际共同日期重算。用户指定的窗口和可计算的较短窗口分别呈现。合同引文保留主体、触发事件、否定词、例外、书面通知与期限；经营指引另附截至时点的履约状态。持续性判断列出最强反方及下一个可观察条件。每个关键分句绑定支持或限制它的已读区间；材料只支持描述时，归因和预测留作未知。[行情工具](../../apps/api/app/research_market_analytics.py) · [分项交付](../../apps/api/app/research_delivery.py)
- **集中反事实验收。** 对同一份研究依次删附注、替换为本期收入口径、调换合同主体或删掉例外、错开交易日、撤销某一来源许可。用研究入口生成结果，再重开原版本和导出。检查应保留和应撤回的判断各自是否正确。词面规则可拦截已知错误；复杂指代、会计范围及竞争解释仅在有独立依据时标为支持。缺独立语义判读时列为未评估，不用模型自评分填充。

### 阶段 4　把完整依据送入上下文，核算整题成本

在普通研究、追问和恢复共用的请求构造处，按分项装入完整证据组、关键反证和未决限制。检查点补记已送材料的来源 ID、版本哈希和字符区间；只有同一版本的对应区间仍在实际请求中才省略重复引文。新材料修订、撤权或容量不足时重新检查整组，保留无关的可用判断。私有记录保存省略原因与截断计数，模型收到可展开的短引用。通过同一原文位于请求首、中、末以及一次续跑，检查旧反证有没有被丢掉。[上下文构造](../../apps/api/app/research_context_manager.py) · [恢复对照](context-evidence-acceptance/context/paired.md)

工具裁剪做独立实验，证据投影和可执行权限保持相同。全量定义与按需激活分别测整题累计输入、已报告缓存命中、额外调用次数、首字延迟、完整交付和工具误藏。原有制表题的首轮定义由 43,709 减至 18,915 字节，但多了一次激活。取得真实回执前保留现行默认配置。密度按“跨调用去重的完整必要证据组数 / 累计实际输入千 token”计算，同时报告绝对覆盖。供应商未提供 token 时另报每 KB，不混合两种口径。[工具呈现对照](context-evidence-acceptance/context/tool-groups.json)

### 阶段 5　恢复真实模型质量评估

先核对已授权 endpoint 对应的配额状态、限流响应、可取得的 Retry-After 和账户并发。上轮三次 429 只证明当时请求被拒，无法判断是并发、配额还是服务状态造成。用冻结基线与候选、同一模型及支持参数、同一来源快照、工具权限和每臂预算另开实验批次；记录源码哈希、启动状态、实际工具交互和回执。已发但结果未知的操作先对账，既往失败原样保留。可用性通过下一条已登记的研究任务验证；连续限流时暂停该供应商批次，有恢复依据后再启动。外部模型暂不可用期间继续离线验收。[上轮预登记](context-evidence-acceptance/delivery/e-preregistration.md) · [实际运行清单](context-evidence-acceptance/delivery/live-results/freeze.json)

两臂交错、同题成对重复，先做财报正反归因，再覆盖条款与行情。按最终用户可见答案评分。核心分项须同时有正确主体与口径、可定位依据、可复算结果或具体限制；没有可评分回答的已启动臂仍进入运行完成率分母。分别报告实际交付、无据归因、关键反证遗漏、已报告 token、延迟、费用未知项。预先冻结判分口径和配对差异门槛，小样本给出原始计数与逐题差异。单方失败不构造配对胜率。

## 三、工程债与最终决策

26 个旧失败按其保护的用户行为处置，可与离线取证工作并行。20 个旧上下文、恢复与结算用例逐一关联到当前入口，优先核对账户隔离、未知外呼防重、预算和部分交付；6 个旧表格用例核对 XBRL 的主体、期间、单位、指标与原表单元格对应关系。仍承诺的行为迁到当前路径集中验收，真正的缺陷修产品，已退役路径留下替代用例或退役依据。交付一张“旧用例 → 用户行为 → 新入口 → 结果”的清单，保留基线失败记录。[失败列表](context-evidence-acceptance/verification.json)

| 决策点 | 建议预登记的通过条件 | 失败后的动作 |
| --- | --- | --- |
| 是否采用新选择器 | 新留存集在相同候选、许可、段数和字节下的完整组数超过 82900b4；反证保留不退化；权限与时点越界 0 次。完整组分子要求全部必要角色同时出现 | 根据语料、候选池及实际选入的差距，返回对应步骤；新一轮调参再换留存集 |
| 是否扩大分析能力 | 实际可核对的核心分项增加，无新增无据归因；正反事实均能按预期撤回或保留；按任务类型披露样本数与未评估项 | 若证据齐全仍答错，修解释、计算或报告组装；若样本不足，结论限于已评估任务 |
| 是否默认开启动态工具 | 同模型、同证据和同权限下，整题用量或延迟有实测收益，完整交付率和合法工具可达性不退化 | 保持显式开关，记录退化发生在激活、恢复还是提交 |
| 是否进入下一轮扩展 | 已有一次可核对的真实成对结果，并能解释改善与退化来自哪里；正式质量门槛在查看新结果前固定 | 供应商不可用时只报告工程验收；扩展研究类型及发布分别决策 |

**首个里程碑**是交付逐题失分表、可复放的同池选段对照和一批新留存题的结果。它能回答最有价值的工程问题：在已有资料与相同容量下，哪些判断原本可以回答，如今确实有了完整依据。
