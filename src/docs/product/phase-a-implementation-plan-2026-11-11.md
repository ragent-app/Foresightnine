# 阶段 A 实施方案：通用金融分析 Agent 的范围与基线

日期：2026 年 11 月 11 日  
状态：2026-11-11 用户决定不等待人工验收，直接进行本阶段收尾；人工评估与正式质量门槛保留为后续验证事项。工作成果和逐项状态见 [执行与验收台账](phase-a/00-status-and-audit.md)。

## 1. 目标与决策边界

本阶段建设[个人投资决策 Agent](fusion-finance-ai-macro-plan-2026-11-11.md)的通用金融研究底座。阶段 A 的目标是明确首批可验证能力、建立可信评估与代码基线，为阶段 B 的首次研究闭环提供实施规格，并为阶段 C 的后续更新准备验证材料。

区分三个层次：

1. **研究底座范围**：通用金融研究与分析，不限定行业、公司或单一市场。
2. **首版实际能力**：由任务、数据覆盖、来源权限、质量、成本和验证结果共同决定，对用户明确展示可用范围及缺口。美股公司研究、全球宏观和中英文是优先验证建议，并非已确定的最终范围。
3. **开发及评估样本**：用具体问题、资料和事件检验系统。首条端到端样本用于开发和调试，其他样本用于检查是否过度适配；样本不构成产品的行业、公司或市场限制。

本阶段不以构建完整新版产品、迁移生产数据、删除旧功能或发布服务为出口。研究和模拟之外的真实下单、资金托管和全市场实时交易信号不属于首版范围。FM 是可选模块或双入口的产品定位仍待评估，本阶段保留现有确定性计算、原始与约束结果区分及客户端计算边界。

## 3. 任务与评估设计

建议初始评估集约 30 个可人工核验任务，具体数量根据资料与人工成本调整。覆盖公司事实与财务计算、跨公司比较、宏观数据解读、事件影响与反方分析、既有研究增量更新等类型；缺失、过期、冲突、来源失败和工具失败穿插其中。包含不同公司或对象和至少一个不同领域的任务，检查方案能否迁移；覆盖范围和比例待盘点后确定。

每项任务记录问题、对象、截止时点、可用资料范围、来源快照与定位、参考事实、确定性计算及公式、反方与未知项、预期输出、评分方法和允许的失败或不确定结果。资料无法合法保存时记录可访问的来源和可保存的定位信息，不擅自复制受限内容。

从开发样本中选一项资料充分、包含首次研究及可验证后续事件的任务，作为首条端到端链路。该事件可采用有明确先后时间的历史资料，以验证更新机制；这不证明系统具备实时监控或前向预测能力。其他开发样本检查不同任务类型；独立测试集不用于提示词、规则或样本选取的迭代。

人工基线至少记录事实准确、引用是否支持主张、计算正确、任务完成度和人工核验时间；更新任务另记变化识别、误报和漏报。依据人工基线与任务风险，在正式对照前预先确定验收阈值、评分规则和失败处理；不根据正式结果事后调整。报告样本量、分类型结果与不确定性，不以接受率、报告长度或回测表现替代质量。

## 4. 代码、数据和来源盘点

记录 ForesightNine 与 `/home/lxx/Openclaw-stock` 的提交、分支、未提交修改、相关运行环境和研究数据位置；不记录凭据内容。保存原始研究资料和历史版本。对于每项候选能力记录代码位置、实际行为、测试或试取证据、改造成本、兼容读取与恢复需求，以及“可复用 / 需改造 / 待验证 / 暂不处理”的结论。

优先核验：研究状态与证据契约、原文与事实及模型解释的区分、公司和证券身份、确定性计算、调用预算与取消恢复、权限隔离、导出；逐项检查旧连接器和模拟数据回退。历史测试记录和文档不能代替当前验证。固定评分、旧回测、账户、计费和部署各自评估，不整体继承其有效性或生产就绪结论。

来源矩阵至少记录来源及支持的任务、覆盖对象、事件/公开/获取/修订时间、财务期间和单位币种、价格口径、凭据与限额、实际成功和故障行为、保存/展示/导出权限依据、成本、替代来源和未知项。一手披露和结构化数据优先；新闻及社媒是后续候选，社媒只作为待核验线索。不得把模拟数据混入真实证据；转载不算独立来源。

## 5. 对照实验与预算

比较通用 AI 加搜索、固定工具流程及新 Agent 时，尽量固定任务、资料快照、时间窗口、工具权限、提示词版本、输出要求和预算；各对照方式无法完全统一的条件单独记录，避免将流程差异误认为单一模型因素。模型或提示词等可控实验一次只改变一个主要因素，并使用重复运行、独立测试集与预先确定的评分规则。

记录模型和供应商、实际支持的生成参数、提示词与资料版本、调用及重试次数、工具输入输出、超时取消、耗时和费用；无法固定的模型版本和在线检索变化也须标注。设定调用、时间及费用上限，耗尽时保留已完成结果和缺口。成本分别按首次研究、增量更新和持续观察归集，包含模型、搜索、数据、文档处理和存储；无法测量的费用保留未知，不自行制定价格或工期。

## 6. 阶段出口及 B 阶段交接

阶段 A 收尾时，以下成果应有可检查的版本和证据；未解决事项明确交接，不视为已通过产品验证：

1. 能力地图区分产品目标、首批候选能力、真实数据覆盖与未支持事项；首条开发样本及其他评估任务清楚标明用途，而不是产品限制。
2. 两个仓库的基线、原始资料和候选复用项已盘点；已知新旧执行基线差异和兼容、恢复要求有记录。
3. 首条样本所需关键来源已实际试取，时间、单位、许可、成本、故障和缺口有记录；无法解决的缺口有替代方案或明确阻塞项。
4. 评估候选、参考答案草稿及评分流程有版本和来源；人工复核、人工基线、独立测试集冻结及正式对照阈值明确交接为待办。未运行的系统对照明确标为待测。正式对照前完成这些验证准备，不以候选题冒充盲测。
5. 有基于测量或可核查依据的成本初估，列出尚未知的供应商费用、人力和时长；模型及供应商选择保持待评估。
6. B 阶段规格定义问题或资料入口、研究与证据对象、来源及工具输入输出、确定性计算、反方、用户复核、结果导出、预算耗尽与失败/取消/恢复，以及逐项验收方式；保留 C 阶段更新与版本衔接。

若关键资料不可用或许可不明，缩小首批已验证能力或更换开发样本，并保留原因；不把缺口解释为产品只能支持某一行业。完成 B 和 C 后，以真实资料检验首次研究及一次有依据的更新，并使用其他任务验证迁移能力。
