# Two natural-question development-model runs

These are two exploratory runs on 2026-11-23, before a subsequent runtime repair. They do **not** replace the separately frozen candidate scorecard or establish the behavior of a later code snapshot. The two prompts and source excerpts are fictional and were not taken from the disclosed frozen corpus. They were not preregistered as a representative test set and are now public. The observations below are manual assessment of those specific runs, not human subject testing or a population-quality estimate.

## Process and controls

The [bridge runner](bridge-run.py) created a mock-authenticated account, uploaded one synthetic user-supplied source per topic, and used the actual local research HTTP entry, persisted version and export. Discovery was disabled; the two runs respectively set a maximum of 10 model calls. The bridge declared a 240-second single-request timeout, 1,800 maximum output tokens in its provider policy, a 235-second file-response wait and a 6,000-character response limit. These are declared harness settings; actual generated token use is unavailable. The Python test process blocked socket connection and DNS resolution. The local sources were searched using the existing source tool; no public search or external data provider was used.

Separate development-model peers wrote the native tool responses and independently reviewed candidate claims via the file bridge. The writer chose and issued actual tool calls in response to the runtime's messages; its responses were not scripted to match an answer key. The reviewer received the runtime's evidence-bound review packets. The bridge translates peer-produced JSON into native model responses; the peers' responses have no usage object, and no model token or monetary cost was recorded. These are development-model calls, not a test of a configured BYOK endpoint. No provider/model version reproducibility, random seed, independent human grade, or monetary total is available. Elapsed time includes the file-bridge peer turnaround and polling and should not be read as product-provider latency.

The source and question, sanitized final parts, reviewer outcomes and proposed versus delivered report are preserved in [sanitized results](sanitized-results.json). Raw tool bodies and temporary account or source IDs are omitted. ## Index eligibility and removal

The source says newly added bonds need at least BBB at the quarterly review; an existing constituent that falls below BBB between reviews is removed at the next quarterly-review close, which occurs on the quarter's last business day. Issuer default triggers removal at that day's close. Thus a B-rated new bond fails the stated entry threshold; the ordinary downgrade exit has a default exception. The source says nothing about other conditions such as rating recovery.

The writer read and searched the source, proposed the correct entry answer, ordinary removal time and default exception, and submitted those as a completed report. The final operation completed, but the saved turn was **partial**, its report was empty, and the removal subrequirement remained unresolved. The source-supported default exception was separately recorded, but the reviewer labeled the ordinary-removal claims `weaker` because those individual claims did not explicitly include the exception. Reviewer outputs across two calls: four supported, four weaker and four irrelevant claim–requirement judgments; these are not 12 independent questions. The narrow supported entry answer appeared as a question part.

The compound original-question part was nevertheless marked `answered` using only the entry answer; this is a false completion signal for the combined question. The separately planned removal requirement remained unresolved, so the final turn did not claim complete delivery. The observed outcome shows both inadequate aggregation of separately supported/qualified conclusions and an inconsistent part-level completion state; it does not establish that a later repair succeeds.

## Household payment deadline

The source says account A's **available balance** can be withdrawn immediately at book principal on any calendar day without an early-withdrawal fee. Product B requires 30 calendar days' advance notice and redeems at a net value that may be below the invested principal. For a payment due in 12 days, the material favors A on liquidity and principal preservation **if** the necessary funds are available and the payment transfer can settle on time. If B notice has not already been given, 30 days exceeds the available period; the source does not establish transfer timing, the status of any previous notice, all account risks or guarantees.

The writer's proposed report gave a conditional preference for A and noted B's notice and loss risks, but stated B cannot meet the deadline without explicitly considering prior notice. The reviewer assessed only the A support claim against the whole decision and judged it weaker because it did not compare B or provide a choice; two such judgments arose from one reviewer call. B's stated terms were saved as counterargument claims. The completed operation produced a **partial** turn with an empty final report and both question parts unresolved. This withheld a useful condition-based comparison as well as the writer's potentially overbroad statement about B's timing. Export returned HTTP 200 in both cases; HTTP success does not mean the analysis was complete.
