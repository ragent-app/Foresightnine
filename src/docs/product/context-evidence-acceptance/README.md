## 可操作的工程边界

- `search_library` 可传现有 `requirement_ids`，省略时按运行当前未满足核心分项取证。资料库保留用户主查询，对各需求的补查只走本地索引。模型收到选入段落、可读区间和省略统计，完整排序轨迹在账户内的私有调用记录。标注的需求关联只说明检索命中。
- 按需工具组由已有的 `FORESIGHTNINE_LLM_CAPABILITY_PROFILE` 显式设置 `native_tools: true` 和 `dynamic_tool_definitions: true`，仍需匹配当前 endpoint、model、version。默认完整工具路径继续工作。模型通过 `activate_tool_group` 提出激活，下一调用才获得定义。阶段 D 已验收结算中断、切换回完整配置、恢复同一批次与外部来源不可用的路径。
- 数值检查额外覆盖跨句误认增量、同一来源混入不同公司、EUR 原文误录 USD、市场序列中途换币、缺发布时间。定位和计算通过的结论仍可由用户复核。用三页[自编 PDF](evidence/cross-page-statement.pdf)经过真实 PDF 转文本、财报提取与第三页回读，原 PDF 的年份被提取器拆行；系统标记 `period_unresolved`、给出页范围和部分结果。附注编号不能自动证实第三页附注，需另行定位。[原始 PDF 回放](evidence/pdf-replay.json)
- 集中业务回归 246 项通过，随后财报定位及阶段 2 组合 20 项通过，两组有重叠。Web 类型检查通过。额外的旧测试集有 20 个相同用例在基线与本版均失败；表格扩展套件的 8 个失败也在基线复现，其中两个原生财报用例已修复，剩余 6 个涉及旧结构化分析路径。保留失败清单供独立核对。[测试归因](verification.json)
- 冻结基线可由上述 Git 提交恢复。在其根目录应用 `delivery/live-results/candidate.patch.gz` 解压后的 unified diff 即可还原真实对照使用的候选 API Python 源。已在隔离目录验证还原结果与运行清单的 B 哈希一致。后续的限流分类、资格校验及边界修复未计入该真实实验。

研究效果仍待可用的授权供应商返回实际回答后评估。工程上优先保留可回读的完整证据组合与独立反证，扩大检索留存样本；默认工具集的调整须等待真实缓存、耗时与回答质量对照。
