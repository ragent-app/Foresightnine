## A：固定候选池的选择

在 `baseline.json` 原样冻结的每题候选池上比较前 K 和按需求选择，候选顺序、内容、授权、截至时点、容量一致。按需求臂只能接收问题、需求描述、候选可用元数据和内容，不读取 `expected_groups`、`expected_missing` 或候选来源 ID 的答案映射。S1 应同时选主表及附注，不由重复转载挤出；S2 应保留主表并指出附注缺口，不能把搜索未命中当成完整资料不存在的证明；S3 应同时保留主表、附注与独立且可能改变判断的客户披露；S4 不得选择截止后或撤权来源。若候选缺失则单报召回缺口，不归咎选择器。比较输出应包括每个候选的需求 ID、选入或省略原因、来源版本和精确位置，作为后续阶段轨迹输入。

## B：查询对照的预登记

单独评估同一冻结语料、许可、时点和同一选择器：问题原文查询对按缺口查询；每题最多 3 次本地查询，每次返回上限 20，去重合并后的同一候选容量再选择。两臂分别记录实际每次查询、触发需求、命中及未命中；基线臂允许重复相同主题查询，不能借此引入需求臂关键词。需求臂先查两期收入，再依已有证据缺口查增长来源及反方，具体措辞只能来自用户问题、需求和已读材料，不得使用评估答案、预标来源 ID、数字或未读取的附注名称。不同候选池覆盖说明查询效果，固定候选池 A 才能归因选择器。两臂一旦执行即保存不可变输入、输出、代码哈希和查询轨迹；目前 B 尚未运行。
