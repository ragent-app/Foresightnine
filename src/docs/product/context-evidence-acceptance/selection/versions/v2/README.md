# 第二版开发冻结

第一版独立保留集未达标；独立题标签未提供给开发者。第一版资料库和工具源码、其选择结果保存在 `../v1/`。这一版在看到独立集整体失败及新建开发集的结果后调整，结果不属于独立验收。

真实入口通过 `research_delivery.assess` 得到的 financial、contribution、counterevidence 需求可能共享同一问题文本，第一版查询完全一样。第二版从已有 kind 和 metric 添加通用的期间、变化、风险等检索词；不向查询传入答案标记。选择时保持原问题候选，结合词面线索、数值与期间、条件词、来源类型及新增词汇；这些均是粗线索，不能确认候选支持需求或构成反证。单个需求仍保留有明确条件的报道原文。潜在误选包括不相关但包含数字或条件的材料；来源类型也不证明直接性，需留存集检查。

`development.json` 是自行编写的开发集，覆盖不同期间、中文与英文、单篇明确报道和条件条款。`replay.py` 由真实前置 assessment 创建需求，而非直接传预写的需求；同资料、相同 K，对比 v1/v2 工具，离线无模型、向量或网络。D1 的候选/选择改善 1/2→2/2；D2 2/2→2/2；D3 0/1→1/1；D4 0/1→1/1。初版调参中 D1 没有召回附注，D3/D4 把泛泛讨论排在明确条款之前，随后调整了查询与定位信号；故不能把这些结果当作未见过的评测。结果是必要来源组覆盖而非语义正确率。

在复制的第一轮固定输入上重新执行线上 A：S1 0/2→2/2、S2 0/1→1/1、S3 2/3→3/3、S4 2/2→2/2。B 两臂为同一工具、需求补查和调用数，改变主查询，S3 原问题 3/3、缺口主查询 2/3，其余持平。两个对照的 512 字节只通过断言确认此语料满足相同上限，真实工具尚未普遍实施字节容量约束。参见上一层 protocol 对基线、B 范围及限制的说明。
