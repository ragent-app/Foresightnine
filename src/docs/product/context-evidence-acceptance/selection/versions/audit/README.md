# 选择与诊断成本审计

在第二版选择策略上只做本次调用内的文本、资格和分词缓存；不改变候选排序。模型可见命中新增 `requirement_match_status: retrieval_only_unverified`，提示需求 ID 是召回关联，不证明语义支持；不同查询分数也不能直接比较。完整候选轨迹和查询原文不会进入模型历史。实际运行仍需读取原文、核对版本与位置，标题或关键词匹配不能充当证据。

工具每次至多 1 条原问题查询加 10 条需求查询，后者强制 BM25 不调用向量服务；原查询和来源索引保留既有配置的向量行为。每查询最多 `max(50, 5 * max_hits)`，按当前 max_hits 上限 20 即 100，因而最多 1100 个查询命中合并前候选；同一精确来源区间合并。完全重复判定比较整个已检索段的原文，只有与已选段逐字符完全相同才标记，非相似度判重或同一原稿判定，转载链和独家新增内容仍需进一步处理。段落常规上限 1200 字符，表格单行例外可达 4000 字符。来源资格和时点在同步和候选输出边界检查；需求 ID 仅来自当前已评估需求或显式有效 ID。

私有诊断由协作者调整为先保留全部 selected，再按顺序填充 omitted，最多 500 条，并记录总数、截断和过滤数量；查询原文只保留哈希。因候选可能超过 500，缺失尾部决策不能被视为未发生。已选最多 20 条，每条模型可见结果含来源 ID、段落位置、摘要及只表明检索关联的需求 ID；按权限允许显示的原文才能再次读取，来源版本或范围变化不能沿用旧引用。默认未设置全局调用或时间预算不因本地查询而改变。

`performance_replay.py` 为合成最坏量级压力样本（20 个来源、2,535,580 字符、2200 索引段、10 个需求、20 个输出、1000 合并候选），同一机器各执行一次、开启 tracemalloc：缓存前检索 14.148 秒、跟踪峰值 2,145,329 字节；缓存后 8.834 秒、跟踪峰值 4,468,256 字节。索引分别 0.719 和 0.955 秒；一次测量有噪声，tracemalloc 影响延迟，跟踪峰值不是进程总内存。缓存限定于单次调用且最多 1100 项，主要交换峰值内存换取减少重复分词和资格检查。不能据此预测真实文档或更高命中规模。

在独立 `audit/` 副本重跑冻结的开发、A、B 输入后，所有选入源 ID 和组覆盖与 V2 冻结一致；这些对照结果不能保证所有输入字节完全不变。定向检索测试 7 项通过。脚本 SHA-256 `5d19ad46052b798046296d3def7e8c38e938ec56afcfa8c23b491230c3a9b3a9`，当前库工具代码 `fc08a9fe8459a6260795e5501f96c5a6767f8b0cbd5f7c822e24c7c09de8f804`。第二套独立复核未全覆盖，性能修复不提升或证明研究正确率。
