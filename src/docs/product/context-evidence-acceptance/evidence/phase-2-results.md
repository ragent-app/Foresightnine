`recheck.py` 对 F1 保存的状态重新组装：撤销附注 model_input 或改变其原文后，90% 不再显示而 20% 保留；记录见 `recheck-results.json`。这是分项重评，不是数据库重开、display/export 撤权或 Web 验收。行情共同时点以实际两端为准，记录其口径；若用户指定日期，需求评估要求与共同窗口一致。双方分别覆盖 2–4 日与 3–5 日时，分析明确共同窗口为 3–4 日；指定 2–5 日的需求评估为 missing，指定 3–4 日才满足。此项为本地行情分析和需求评估联合验证。

计算输入按来源权限、原文范围和已知旧版本散列重验；每个定位引文须有同名主体的来源声明，贡献句须明确关联该主体；同一来源也不能省略此检查。该声明不是身份核验。主表当期和基期要求同一标签、相同或可安全换算的币种单位、可比较且有序期间；附注需提到两期及变化贡献。词面门槛不能证明主体、范围或因果语义，所有相关判断保留人工或独立语义复核状态。零增量拒绝计算，负增量按带符号数计算，不默认解释其经济含义。没有外汇换算工具，跨币种拒绝而不是猜测汇率。

财报抽取返回已读页面的 `context_ranges`，包含可回读表头/单位的页范围；有附注编号时标记正文未随主表读取，不能把编号当作附注内容。离线两页表格验证两页范围、期间与单位，并以独立 read_pages 读取第三页附注；附注正文尚未自动绑定到事实。续页列头倒置时原实现错误沿用首页，现标记冲突、隐藏受影响页面的数值并保留可定位范围；真实 PDF 端到端尚未验证。事实数值和引文定位不证明表格语义。

定向业务回放及 `test_context_evidence_stage2.py`、研究需求、报告、分项和单个财报抽取测试共 33 项通过；生成的 V2 TypeScript 契约检查通过。另一次扩大测试中，43 项通过、8 项失败：工具排列旧预期、无 hash 的旧事实输入及六项旧结构化分析草稿不匹配；这些失败尚未完成归因，不能将表格全套验收标为通过。无模型、搜索调用，真实质量、投资有效性以及上述未覆盖边界保持未验证。

手工计算入口与重算入口对新增归因公式返回 422；公开请求契约不提供该公式，研究工具执行时才检查定位、范围和期间。独立 API 请求与模式检查已验证。

针对独立复核提出的反例，`adversarial/` 保存独立输入、回放脚本及原始结果：跨句把“当期收入贡献”和“整体增长”相邻但没有连接、同一来源内另一主体披露增量、EUR 附注错误录为 USD。修复后均只保留原主表的 20% 增长，错误增量主张与 90% 计算未持久化；原 F1 仍有 90% 且为部分完成。重放时将对应 `*-input.json` 和 `replay.py` 放在同一目录，输入命名为 `frozen-cases.json`，以 `PYTHONPATH=src/apps/api src/apps/api/.venv/bin/python <目录>/replay.py` 执行。规则只建立保守词法条件和来源声明，不验证复杂指代、会计范围或经济因果；合法表达未命中时保留缺口。

后续主任务完成三页 PDF 实体回放、用户查看和导出验证，以及旧表格失败的归因，最终状态见[验收汇总](../README.md)。当前 PDF 样本是自编材料，支持 PDF 解析到定位、附注回读和已知缺口的工程结论，不代表真实发行人披露的抽取准确率。
