# 研究 Agent 修复方案

2026-11-23。本轮交付为实施方案。目标是在同一研究预算内，让有依据的结果走到用户面前，并验证 Agent 能否主动提交一份逐项可核查的研究答复。

## 一、故障与实施顺序

| 顺序 | 断点 | 已有证据 | 验证办法 |
| --- | --- | --- | --- |
| 1 | 合法的计算意图在工具入口被整批拒绝 | D1 四条轨迹第三轮都出现两种输入写法。逐个比对原始 ID，五个重复填写的计算项中，两种写法的 ID 和顺序全部相同。两条 A 均用完第四轮重发计算。 | 用四次原始请求及调用前状态回放，只执行该次计算。 |
| 2 | 已有证据在答案组装时丢失 | 上批 14 轨中，4 个有已存事实和计算支持的核心项漏显 1 个。另有 5 个核心项，成功读取的原文明确写出限制，候选答案均未具体披露。 | 锁定原终态，比较 API、页面和导出的逐项答案。 |
| 3 | 多数截断发生在早期，可用工具动作尚未产生 | E1 的 12 条截断中，11 条在读取资料后的第二次模型调用。后续分批实验的 8 条截断里，5 条只观察到 thinking 块。末轮提交指令在 7 条实验轨中只送入 provider 2 次。 | 对齐首次读取后的请求、返回和持久化回执。模型侧干预单独做受控配对。 |

第三项影响面最大，前两项先落地，因为它们有真实失败输入和可判定的正确输出，且会直接影响后续实验的评分。上轮两臂正式提交均为 0/7。四次计算获救也不能推出会多出四次提交。[E1 截断审计](research-quality-acceptance/fact-batching/trace-audit.md) · [截断结构](research-quality-acceptance/fact-batching/mechanism-conclusions.md) · [逐题终态审计](research-quality-acceptance/last-call-submission/audit-results.md)

## 二、先修计算工具契约

**改动位置**　`research_tools_registry.py` 的 `CalculationPlan` 和 `research_tool_executor.py` 的 `_exec_calculate_financials`。计算继续经过现有金融公式、输入来源和单位校验。当前校验会拒绝完全相同的双写，却允许数组同时带半个二元输入，执行器在后一种情况下直接使用数组。

1. 模型可见的工具定义统一用有序 `fact_ids`。在同一处写明各公式的顺序与基数，例如增速为「本期、上期」，差额为「被减数、减数」，贡献率和加权平均沿用各自的输入数量与校验。核对实验所用 Messages 协议实际发出的工具定义。
2. 在执行入口把现有合法二元输入转换成同一种有序表示。完整双写且按顺序完全相同时只计算一次。逆序、ID 冲突、只有半个二元输入、无效公式参数或来源失效时，返回具体计算项和原因，整批不写入。调用审计保留原输入，计算记录保留实际采用的有序事实 ID。
3. 保持原有批次原子性、来源权限、资料版本、重试防重和数值精度。在应用内列出直接调用该工具的入口，核验合法请求的结果、单位及引用与修复前一致。

**阶段出口**　集中回放 D1 第三轮的 4 次调用。4/4 批应接受，原请求中的 11 个计算项各有一条可追溯结果。各批收入增长均为 20%；A1 只请求 EPS 相对变化，预期 50%；其余三批另请求了绝对差额，预期为 +1 美元/股。对照运行冲突 ID、逆序双写、半对、失效引用和一批中夹有无效项的反例，错误落库为零。只比较截至该工具回执的结果，成功后的第四轮由真实模型实验观察。[四条原始工具轨迹](research-quality-acceptance/last-call-submission/results/)

## 三、让每个答案分项对应到正确证据

**改动位置**　`research_evidence_requirements.py` 选择证据，`research_delivery.py` 组装答案，`research_partial_answer.py` 合并检查点。被动终止和正式提交处理器已经调用同一个 `assemble_parts`，应沿用这个入口。当前财务判断会按公式名字包含 growth、change 或 difference 筛选并在首个匹配处停止，可能选中 EPS 增幅，同时跳过已存的 subtract 差额。

1. **按所求量选择计算。** 对每个核心要求识别指标、主体、期间、目标量和单位，再核对公式、输入 ID、顺序、结果及引用。分别处理相对增幅、原单位差额、百分点差和水平值。问法允许多种变化口径且两种已存时，直接展示两者并标单位。只有相对变化时照实展示；冻结评分要求的绝对差额仍列缺口。避免把 D1 的评分约定推广成所有「变化」都只接受差额。
2. **把材料明示的缺口写成有出处的说明。** 在现有成功读取区间及资料版本上，优先使用可定位的明确否定原句或已授权的结构化覆盖信息。记录所缺的主体、期间或基准、来源位置，以及受影响的计算。D2 应能说明「这份材料未披露 2024 年稀释 EPS，因此无法计算同比变化」。D4 应能说明「两条观测都是 Delta，材料没有基准，因此无法计算基准或超额收益」。未读取、只读到无关段落或出现歧义时，显示「尚缺可核验依据」。投影时复核访问权、时点与版本，避免把局部缺口扩大成全市场判断。
3. **统一分项状态和交付文本。** 用同一核心要求 ID 合并已存检查点、合格计算和缺口。已答项清除过时的「尚未回答」，一个问题中的多个指标或独立限制分别保留。同一分项可以同时显示已知数值和仍缺的条件。问题要求计算且缺输入时保留 partial；问题本身询问「该材料是否披露」时，带定位和足够检查范围的否定结论可以回答该问题。被动 partial 保留原终止原因与提交状态。

**阶段出口**　锁定上批 14 条轨迹的原终态，使用真实入口统一重放，不混入前一阶段新算出的值。4/4 个原已存有据项应完整显示；5/5 个有明确原文的负向项应带出处并说明计算影响。D1-A2 应显示 +1 美元/股，D1-A1 应保留只有 50% 的限制。D3 原轨没有保存行情计算，D4-B1 连读取都未成功，二者不得凭测试答案补值。逐项比对 API、用户页面与导出，保存一个覆盖正常答案、缺证和被动终止的集中验收记录。核心项误判完成、重复矛盾行、越权或过期引用均须为零。另用调换指标、期间、主体和资料版本的反例检查泛化。[旧批逐轨评分](research-quality-acceptance/last-call-submission/scoring-results.md)

## 四、把早期截断单独列为模型实验

先用既有轨迹对齐「实际读取范围 → 下一次请求构成 → stop reason 和可见块类型 → 工具执行回执 → 首个可追溯事实或明确缺口」。历史字段缺失记未知。按题统计成功读取后进入下一次调用的轨数、该次截断数、首次有效证据落库数。核对资料是否被重复放入请求、重复部分的字节数和占比。保留工具及资料内容的摘要与哈希，沿用现有隐私边界。

先做一次**工具契约**的端到端对照。两臂都包含第三节交付修复，A 使用旧计算契约，B 使用第二节新契约。若计算回执改善而正式交付持平，登记为工具修复有效、正式交付无可见提升，然后转向早期截断。下一次实验不再复测末轮提示。

**早期截断实验的候选变量**为首次读后请求中可证实的重复资料表示。只有冻结构造器能复现重复、且去重后每个独有原文区间、来源定位、工具和权限都保留时，才采用这个候选。A 保持原请求，B 只去掉重复副本，干预放在首次成功读取后的下一次请求。先核对两臂除这一处以外的请求构造一致。已有观测尚未证明重复存在或导致截断；若缺少这个前提，停止该分支并记录诊断结果。调整单次输出上限或推理参数需要另立预算实验。

**实验冻结与停止条件**

- 沿用 D1–D4 的题目、资料哈希和原事实记录策略，沿用上批模型标识、Messages 协议、工具权限及采样设置。每轨最多 4 次模型调用、160,000 核算 token、单次输出 2,048、总计 180 秒、单请求 90 秒、外部搜索 0 次。记录实际支持的参数、模型版本可锁定程度及缓存变化。这些限额只用于该实验。
- 每个单因素批次四题各两次配对，共 16 轨，按原 ABBA 顺序串行。逐轨记录干预实际送入 provider 的轮次、工具执行和提交回执、token、耗时、终止原因及可得费用。原批 D4-B1 结算未知，保留原记录。新批按既有停批规则处理未知发送或结算，不自动补跑。
- D1–D4 仅能验收开发样本。保留独立未用于调参的样本和评分版本；正式扩展结论还需要独立评估。若某批只修复了 D1，可报告该题差值，其余题仍列在分母内。[原冻结条件](research-quality-acceptance/last-call-submission/preregistration.md)

## 五、判定成败

| 指标 | 分子与分母 | 决策用途 |
| --- | --- | --- |
| 正式提交率 | 处理器接受且持久化的提交运行数 / 已启动运行数。另列主动 partial 和 completed | 观察模型是否完成正式交付 |
| 正式有据回答率 | 正式提交中逐项通过冻结证据标准的核心项 / 全部已启动运行的预登记核心项。缺少整份正式提交时，其核心项仍进入分母 | 防止只统计成功提交的题 |
| 终态实际可见的有据回答率 | 正式或被动终态中，用户实际可见且证据合格的核心项 / 同一分母。正向计算和有据的负向披露分别列出 | 衡量用户实际收到多少 |
| 漏答与缺证误判 | 已具备合格证据却漏显的核心项 / 具备合格证据的项；另列资料缺口被判完成、无据数字、误用基准的逐题计数 | 拦截靠少答、错答取得的提交提升 |

集中验收时同时列出四题逐对差值、干预实际曝光数和资源账本。已启动、未启动、结算未知分别报告。正式提交样本为零时，提交内部的遗漏率为「无样本」。两项主指标均上升、且逐题未引入漏答或缺证误判，才可报告本批同时改善；任一项持平、下降或证据不足，都分别照实报告。单题进步、一次小批结果或离线回放均不足以宣布总体研究质量提高。

实施可由三人分工负责工具契约、证据交付、独立回放与评分。先冻结用例，再分别实现，按上述阶段集中验收。开发文档与运行证据放在现有 `research-quality-acceptance` 目录，新结果与历史原轨分别存放。
