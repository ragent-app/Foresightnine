# ForesightNine 研究资料、证据选择与上下文改造实施方案

**状态**　已按阶段开展工程改造。本次交付、已验证边界、独立复核与供应商限流记录见[阶段验收记录](context-evidence-acceptance/README.md)。分析基线为本地 master 的 3e1ca4d，设计日期为 2026-11-23。以下将既有观测、拟开发能力和未来验收条件分别表述。

**目标**　让研究者得到可核对且能帮助修订判断的回答。在相同资料、权限和输入容量下，优先把能回答核心分项、区分竞争解释或推翻当前判断的材料送到模型。成功以独立题的有据回答和错误归因为主判据，输入密度、耗时及成本解释效率。

**首个可交付版本**　用户输入“这家公司的收入增长能否持续”，工作台能从财报主表和附注取得两期可比数字、拆分已披露的增长来源、展示无法归因的部分，并给出下一次复核条件。移除附注后，增长率仍可核对，收购贡献判断随之撤回。第二条链用事件窗口和基准行情检验泛化。采用现有协调 Agent、工具、计算和研究版本；内部直接重构。发布仍需单独授权。

## 1. 设计依据

| 环节 | 本次观测 | 工程含义 |
| --- | --- | --- |
| 请求构造 | 使用现有 recovery_wire_size 的 Messages 配置，分别对 paired.make_input 的 recovery/B 和 facts/B 检查一次请求。恢复题正文 136 字节，请求 52,825 字节；收入题正文 101 字节，请求 54,592 字节。每个请求都带 23 个工具，工具数组序列化后 43,302 字节，system 字段 6,976 字节。单是图表和表格定义就分别为 5,609 和 3,787 字节。 | 短题的工具定义约占请求体的 79%–82%。先测静态前缀、缓存和任务工具选集，再决定如何压缩材料。这是 UTF-8 字节分解，没有测出有效 token 占比、实际费用或正确率变化。 |

现有可复核入口包括[原生运行循环](../../apps/api/app/research_runtime.py)、[请求构造](../../apps/api/app/research_context_manager.py)、[资料库排序](../../apps/api/app/research_library.py)、[原实验和历史回放](research-delivery-acceptance/evaluation.md)。请求体数字可用该验收目录中的 paired.make_input 和 recovery_wire_size 的 provider 重建，对 wire 的整体、tools、system 和 messages 分别执行 canonical_json_dumps 后取 UTF-8 长度。

## 2. 从用户的问题到可修订的结论

1. **分解问题。** 协调 Agent 为每个核心分项写清对象、研究时点、待判断的问题和需要共同出现的证据。例如，同比增长需要两期可比值；持续性判断还需要驱动因素、可替代解释和下一次可观察的条件。简单事实题只建必要分项。
2. **选择下一份资料。** 先查主题已有、仍获授权的事实、计算和原文。若缺收入基数就取对应期间主表；若基数齐全而增长来源不明就取附注；若已有附注，再找能支持或推翻持续性的独立材料。选择理由写入取证记录。
3. **读取和验证。** 检索命中先作为线索。原文读取器核对版本和位置，财务工具核对期间、币种、单位及计算输入；对于含义、归因或矛盾，保留解决它所需的原句及限制。
4. **构造本次请求。** 选入与当前分项有关的依据、重要反证和明确缺口。模型可以回读原文、请求另一种解释所需的材料、调用计算，或提交已有成果。
5. **交付并保存。** 每个分项分别展示判断、依据和局限。新的披露、口径变更或撤权触发受影响分项的复核。更新用户已确认的核心判断时，按现有研究版本展示差异和接受记录。

举例：两期收入为 100 和 120 百万美元，本期增量是 20。若已读附注明确披露“收购贡献了本期增量中的 18 百万美元”，可复算收购贡献占增量的 90%。剩余 2 的驱动仍未知。若附注只披露“被收购业务本期收入 18”，则缺少上期可比范围和并表日期，不能直接套用 90%。两句话数字完全相同，验收要求系统给出不同判断。

## 3. 数据契约与存储位置

沿用现有主题、分项、需求、来源、已读区间、事实、计算和主张 ID。下表字段为拟议增量；开发时优先扩展既有对象。只把可复核的研究状态写入研究版本，供应商诊断留在私有运行记录。[当前分项与引用契约](../../apps/api/app/research_topics.py) · [运行诊断](../../apps/api/app/research_diagnostics.py)

| 对象与位置 | 最小字段与关联 | 写入和失效规则 |
| --- | --- | --- |
| 证据需求，主题分项及运行检查点 | 现有 requirement_id、part_id、是否核心、实体与证券、期间或窗口、口径、待区分解释、所需证据组合、已有引用与缺口。复用 satisfied、partial、missing、unavailable、conflict、not_applicable。 | 一个需求可引用多份来源，同一来源可服务多个分项。稳定 ID 在同一运行及续跑中复用。报告期或问题变化时保留前一版本和变更理由。 |
| 来源线索与候选段落，发现记录及资料库 | 来源 ID 或允许获取的线索句柄、发布方、取得方式、原始出处/转载关系、时间、可用权限、命中位置、关联需求。来源身份带确认状态。 | 新闻聚类和规范 URL 复用现有逻辑。相同字符范围或同原稿可折叠展示；独家新增段落独立保留。搜索摘要仅标为线索。 |
| 已读证据组，由版本化研究对象和引用组成 | 需求 ID、事实/计算/主张引用、来源版本或内容哈希、字符/页/表格位置、期间与单位、证据作用、必须共同出现的引用、未决限制。 | 精确定位、算术匹配和语义支持分别记录。两期增长的输入必须成对，行情比较需两只证券在共同日期的对应值。重读/retry按来源版本和位置去重，保留不同口径。 |
| 调用清单，私有执行记录 | operation_id、call_id、资料截止时点、工具组版本、选入与省略的需求/引用 ID、原因、请求哈希、分段字节数、可取得的 token 与缓存用量。 | 最终序列化时关联同一次调用；回执按 call_id 结算。记录可诊断的 ID、类别和数量，受限原文仅存于有许可的来源对象。 |
| 分项判断，研究版本 | 已有事实、计算、主张及其引用；结论成立的条件、反方、哪份新资料可能改变判断。 | 完成度由服务端根据需求和证据组核对。发现较早引用失效时标记相关分项待复核，其他仍有依据的项可单独交付。 |

首版使用现有研究存储和检查点承载新增字段。只有在按需求或版本查询成为可测瓶颈时才单独建索引或拆表。跨版本定位须保留源版本，不用字符位置去匹配已修订的新文本。

## 4. 资料发现、召回与证据选择

**来源路由。** 输入为需求、账户许可、截止时点和已覆盖来源。财报数字优先用监管披露、发行人披露及可定位的结构化数据；增长驱动找附注、分部披露或有归属的管理层说明；市场表现取行情和交易日历；市场预期需事件前可得材料。外部搜索没有授权时只处理本地资料；显式空来源且仅另行授权搜索时只发现线索。按用途分别检查获取、模型输入、展示和导出许可，外部嵌入或重排也需相应许可。遵守项目现行 FRED 禁用边界。[来源策略](../../apps/api/app/research_source_policy.py) · [来源能力路由](../../apps/api/app/research_source_catalog.py)

**查询生成。** 每条查询关联一个待解需求和预期结果，例如“找到本期与上期的合并收入行”，或“找到合并范围变化对同比的影响”。先使用问题中已有的实体、标签、同义指标、财务期间和文档类型；从首轮已读材料取得公司自己的指标名称和附注号后再定向补查。保存实际查询及触发原因，防止把实验标准答案里的关键词泄漏给查询生成器。

**候选选择。** 复用 BM25 和配置允许时的向量融合，先得到较宽候选池，再按以下顺序做确定性选择。首版不预设跨市场通用的固定打分权重。[资料库召回](../../apps/api/app/research_library.py) · [现有搜索接口](../../apps/api/app/research_library_tool.py)

1. 在检索、读原文和发送给模型三个边界重新校验账户、用途和时点。区分发生、公开、取得和修订时间。关键身份或公开时间待核的候选可保留为待查线索，不能直接证明事实。
2. 将候选关联到尚缺的核心需求。优先选择能补齐一组比较、给出原始定义或解释冲突的材料。已覆盖同一事实时，下一份资料应增加新口径、独立核验或相反解释。
3. 按可确认的原始出处折叠重复内容，保留转载链；同一发行人的主表和附注可同时入选。仅内容相似时标为疑似同源，给出判断依据。不同域名不自动计作独立证据。
4. 在同一优先级内，依次考虑来源直接性、定位精度和新增输入量，最后按稳定 ID 和位置排序。对可能推翻主结论的冲突单独保留位置。输出选入及落选原因，允许模型因口径不明请求重新展开。
5. 已满足本轮核心需求且再检索只会重复时，转入分析。有重要缺口但资料不可用、预算耗尽或外部结果未知时，交付已有依据和具体缺口；只有出现新的授权路径、未尝试材料或新的研究问题才继续相应动作。

**读取粒度。** 表格同时返回行名、列头、币种、倍率、期间和必要脚注；条款返回主体、否定、例外及生效日期；行情返回标的、交易所、日期、价格类型和复权口径。缺跨页表头或 OCR 数字不可靠时，优先回读相邻页/原表；仍不能消歧时保留冲突。返回给模型的短引文可以展开到完整上下文。[表格原文追溯](../../apps/api/app/research_table_provenance.py) · [财报提取](../../apps/api/app/research_statement_extraction.py)

## 5. 上下文构造与工具呈现

在普通研究、追问和中断恢复中共用现有请求构造入口。每次构造必须能够从调用清单追到模型实际看到的来源与版本。[运行入口](../../apps/api/app/research_runtime.py) · [上下文管理](../../apps/api/app/research_context_manager.py)

| 构造顺序 | 拟实施行为 |
| --- | --- |
| ① 确定边界 | 取得当前 wire 协议能力、可验证的单次容量、输出空间、权限、未结工具配对。用户未设的模型调用数、搜索数、总 token、费用和时长上限继续留空，显式零照做。不同协议分别执行容量估计。 |
| ② 确定本轮任务 | 放入原问题、当前分项、研究时点和关键待解点。优先从已验证状态调取证据，跨轮按问题和依赖关系召回较早的重要依据，同时保留用户确认的判断及其版本。 |
| ③ 装入证据 | 优先装入核心需求的完整证据组及足以改变判断的反证，再加补充依据。以证据 ID 去重；在已保留的工具配对中存在完整原文时只加引用。记录因权限、过期、重复、容量和不相关而省略的区别。 |
| ④ 处理放不下的输入 | 先压缩已消化的历史输出和重复线索，再缩短可展开原文。若关键两端或例外条款仍放不下，将子任务分开取证并持久化，最后合并依赖；缺一端时标记部分完成。 |
| ⑤ 呈现工具并发送 | 从当前注册表形成稳定工具组。共同动作包括读取、补证、保存、计算和提交；需要图表、行情或外部获取时才展示相应完整定义。对任务转向提供简短的已授权能力列表和激活入口。服务端逐次校验调用。需要完整注册表或固定续接定义的协议保留受支持路径。 |
| ⑥ 记录与恢复 | 序列化后记真实字节数和请求指纹，发出后记供应商回执、截断及实际用量。工具调用与结果保持配对，未结批次固定其工具集版本；未知外部结果进入对账。恢复时从证据状态重建当前问题，避免重发同一未知调用。 |

工具裁剪单独立项评估。稳定前缀可能已有缓存收益；候选策略须同时比较冷/热缓存、未命中输入、首字延迟、激活额外调用和误藏工具率。字节数下降而完整作答率下降时，优先检查工具可达性。[工具注册表](../../apps/api/app/research_tools_registry.py) · [恢复逻辑](../../apps/api/app/research_recovery.py)

## 6. 分析、产品呈现和故障处理

研究者打开每个分项，先看到答案和口径，再能展开数值、公式及授权原文。定性判断需要讲清证据能支持到哪一步、另一种可行解释是什么、哪项观察能区分二者。对于只问数字的问题，交付数字、期间与来源即可。对于投资时点或期限，区分配售价与可交易入场价，给出条件和复核事件；缺少定价依据或退出条件时显式保留未知。历史行情的正确计算本身不足以验证投资效果。[报告校验](../../apps/api/app/research_report_grounding.py) · [分项组装](../../apps/api/app/research_delivery.py)

| 事件 | 系统行为 | 用户所见 |
| --- | --- | --- |
| 新增四篇相同报道 | 原稿与重复证据引用复用，保留各自来源记录；单独处理新增段落 | 来源列表可展开，结论强度不因转载数量上调 |
| 新旧披露冲突 | 核对主体、期间、口径和修订时点，保留两侧出处 | 截至该时点的结果、冲突原因或尚未解决的问题 |
| 来源撤权或修订 | 读取、提示、页面重开和导出逐层检查；失效证据及依赖它的计算、归因重新评估 | 仍有依据的分项继续显示，受影响分项显示待复核及缺口 |
| 供应商断流或预算用完 | 已确认读取、事实和计算持久化；同一证据状态下重复失败沿用现有停止与对账机制 | 可用的部分成果、停止原因、实际用量及未完成项 |
| 新证据改变已确认判断 | 计算受影响主张，生成旧判断、新建议、依据差异 | 用户可接受或保留原判断，历史版本可追溯 |

## 7. 分阶段开发清单

按下表顺序实施。每个出口采用一组连贯的业务验收，失败时只针对具体回归补测。各阶段为工程交付顺序，整体正式质量验收单独记录。

| 阶段与主要职责 | 具体工程改动 | 可交付物与出口 | 未达标时 |
| --- | --- | --- | --- |
| 0　运行时与评估 | 在请求构造、协议序列化、工具回执、分项提交处关联 operation_id、call_id、requirement_id；统计互斥的字节类别及序列化开销。建立按分项的候选→已读→入模→采用→交付轨迹。 | 冻结现行对照；用同一财报题和行情题重放，能指出每个缺项首次消失的位置。已报告用量、估算与未知可分开复算。 | 先修观测盲区，避免在无法归因的基础上调策略。 |
| 1　取证与资料库 | 接通需求到查询、来源路由、较宽候选池和排序理由。先固定候选池对照选择器，再单独改查询。 | 同等输入容量下，主表和已存在的关键附注均入选；重复报道不能挤掉必要披露；无附注时正确指出缺口。交付选材轨迹。 | 候选无原文查获取与查询，候选有原文查过滤、排序和去重。 |
| 2　读取与金融计算 | 扩展现有读取结果及引用，绑定表头、期间、脚注、来源版本和计算输入；接入两类证据组。 | 重算收入增幅和同窗口超额表现，验证单位、汇率或缺交易日时的处理。删去一端，相关计算不再作为有据交付。 | 修复原文定位或计算边界，保留与缺口无关的成果。 |
| 3　运行上下文与协议 | 先接普通、追问、恢复共用的证据选择；以独立开关实验任务工具组。沿用现有检查点、账本及并发版本保护。 | 同一事实跨轮可复用；旧而重要的反证仍能进入请求；任务转向可启用合法工具；中断、撤权和重开后无错误配对或重复外呼。 | 用调用清单定位误删，证据投影和工具子集分别修订。 |
| 4　交付与独立评估 | 分项关联证据、计算、竞争解释和观察条件；前端展示与导出同版本同权限。执行集中受控真实对照。 | 完整、缺失、冲突、中断四类结果均可重开核对；独立题的有据回答、错误归因、密度、成本和失败均有原始记录。 | 依故障位置退回前一相关阶段；语义或投资效果证据不足时保留未验证状态。 |

核心改动落在 API 的研究运行时、资料库、工具执行器和研究版本持久化；Web 沿用分项和证据视图。修改公开研究数据结构时同步 OpenAPI 和生成的 TypeScript 契约，内部调用清单不自动进入对外 API。阶段 0 用实际调用数、处理耗时和资料规模估算人力与实验预算，再排后续工期。[研究持久化](../../apps/api/app/research_turn_persister.py) · [Web 分项视图](../../apps/web/src/pages/topic/QuestionParts.tsx)

## 8. 对照设计、判分与扩展条件

**样本。** 首批可按项目建议准备约 30 个可核查任务，覆盖财报与附注、事件与基准、定性条款与反证、追问与更新，含中英文、冲突、缺数、撤权及工具故障。建议开发/调参/独立留存各 10 题；按实体、原始文档和事件分组切分，防止同稿转载跨集。首次财报链只用于开发。独立集冻结题目、资料版本、截至时点、核心分项、可接受的等价证据组、允许或应撤回的结论、正确缺口，运行时不可读取答案标签。

| 对照 | 唯一主要变量 | 必须固定 | 主要观察 |
| --- | --- | --- | --- |
| A　离线选材 | 前 K 段与按需求选段 | 同一候选池、来源、排序输入、证据容量 | 必要证据覆盖、反证保留、重复原稿占用 |
| B　资料获取 | 主题查询与按缺口查询 | 同一冻结语料/搜索回包、选择器、搜索与获取额度 | 必要材料进候选池的比例、重复获取及来源缺口 |
| C　上下文 | 现有历史拼装与按分项装入证据 | 同一批已读证据、完整工具集、模型与生成参数 | 已读到入模的损失、有据回答、错误归因 |
| D　工具呈现 | 完整定义与按需展示定义 | 同一证据投影、可执行权限、模型和预算 | 体积、缓存、激活成功、完整交付与延迟 |
| E　端到端真实运行 | 冻结基线与通过前述验收的组合版本 | 任务、许可、资料快照、模型协议、支持参数、调用/时间/费用边界 | 是否能交付有据判断，以及在哪些任务上改善或退化 |

真实实验执行前填写并冻结每臂的具体预算、停止条件、评分规则和版本哈希；采用成对重复及平衡顺序，分别报告冷/热缓存和受限请求。记录模型标识、工具交互、调用/重试、耗时和实际回执；未提供账单时费用未知。实验额度不会写入产品默认设置。人工复核按项目约定跳过时，已定位和可复算的结果照常验收，依赖独立语义判断的项目单列未评估。最后的组合对照只能说明系统总体表现，各单项贡献看 A–D。

| 指标 | 分子与分母 | 用于判断 |
| --- | --- | --- |
| 分阶段证据覆盖 | 当前阶段完整出现的必要证据组数 / 可取得的预标必要组数；候选、已读、入模各算一次。不可取得项单报具体缺口正确率。 | 丢在资料获取、选择还是上下文 |
| 有效信息密度 | 实际请求中互异的必要证据组数 / 该请求实际输入千 token；整题分子跨调用去重，分母累加所有输入。无法得知输入 token 时另报每 KB。 | 与绝对覆盖一起看，防止通过少发证据提高比值 |
| 有据回答覆盖 | 主体、期间、口径、数值、证据及推断均达到预定规则的核心分项数 / 冻结的核心分项数。执行失败仍保留在总分母，未判读的语义单列。 | 研究者实际拿到了哪些可靠回答 |
| 错误与反事实 | 分报证据不足误报完成、证据齐全误报未完成、无依据归因、关键反证遗漏；报告各自可评估分母。对预先配对的撤回/保留主张逐项核对。 | 结论能否随真正有意义的材料改变 |
| 效率 | 模型与搜索调用、已报告 token、墙钟耗时、可核账费用 / 有据分项数；另报完整交付数和零交付运行。分母为零时保留未定义。 | 较低成本是否来自有效交付或提前失败 |

**工程出口。** 必须通过明确的权限、时点、两端计算、版本恢复和反事实用例。至少检验四种变化：删除关键附注只撤回归因；把“增量贡献”替换为“本期收入”后不再给出 90%；增加转载不增强判断；缺共同收盘日时不输出伪精确的相对表现。硬约束失败先修复。

**质量出口。** 正式阈值在取得基线后、查看独立集结果前预登记，保留质量最低可接受差异和错误归因退化边界。分任务报告成对改善、持平、退化和样本量。只有在有据回答达到预设目标、重要反证和错误归因达标、收益能在独立任务重现时，才扩展到更多研究类型。密度提升或请求变短本身不构成质量通过。若样本不足，结论限于已覆盖场景。

**首轮执行范围。** 首轮交付阶段 0，并以“财报主表＋附注”完成阶段 1 的离线对照。该轮结束应能给出一张逐题归因表和一项明确决策：缺证发生在候选池之前，优先改来源与查询；缺证发生在候选池之后，优先改选择；关键依据已进入请求仍答错，转入分析和交付修复。后续再投入协议工具裁剪和真实模型预算。

位置对照可将同一反证放在请求首、中、末，检查判断是否稳定；财务计算以可执行程序与输入定位核验。这两项研究提供实验方法参考，本项目表现仍需按上述对照实测。[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) · [FinQA](https://aclanthology.org/2021.emnlp-main.300/)
