# 阶段 B：研究 Agent 宏观框架与整合顺序

本文件细化[宏观方案第 13 节](../fusion-finance-ai-macro-plan-2026-11-11.md#13-系统性架构改进2026-11-13)和[阶段 B 规格第 7 节](06-phase-b-spec.md)的工程边界。它是建设框架，不是完成声明；实际状态以[当前验收记录](208-stage-b-current-audit.md)及代码为准。

## 一、系统整体

```text
用户问题 / 已授权资料
        ↓
研究协调层：任务范围、计划、预算、状态、检查点和部分交付
        ↓
工具层：来源发现与读取 / 文档解析 / 金融数据 / 确定性计算
        ↓
研究层：证据与事实 → 结论、计算、反方和未知 → 有界核查与补充
        ↓
研究状态层：账户、主题、资料、运行、版本、用户判断与来源关系
        ↓
工作区与交付：计划和进度、证据与计算、编辑复核、保存重开、导出
```

一个研究协调器调用受控工具。模型负责理解、规划和解释，确定性代码负责约束、计算和可追溯记录。工具结果与外部文件是不可信数据。任务可以按需要跳过步骤；失败、预算不足与资料不完整应保留已完成结果并明确状态。执行完成、引用可定位、语义支持及用户确认是不同概念。

## 二、阶段 B 的模块边界

| 边界 | 职责 | 当前接入与剩余工作 |
| --- | --- | --- |
| 研究入口与任务 | 接收问题或资料、范围、时点、工具权限与预算；生成运行输入快照 | 工作区、运行请求和快照已有；需要统一任务及步骤契约，避免入口和调用路径各自解释状态 |
| 协调与运行 | 编排计划、取证、分析、复核及交付；记录用量、取消、幂等、检查点和失败 | 当前流程主要集中在 API 入口及运行服务；逐步迁移为协调器和阶段处理器，保持已有持久化和恢复语义 |
| 来源与工具 | 统一来源资格、权限、时点、选段范围；通过适配器访问资料和结构化数据 | 文档、SEC 和官方来源已有适配；来源资格与记录先抽为共享边界，其他工具继续按用途解耦；覆盖和许可不可外推 |
| 研究与审查 | 按任务组织来源、事实、计算、主张、反方、冲突与未知 | 已有处理组件，但分析模块包含大量历史特例；保留必要保护，逐步以通用检索、显式关系和证据审查替代，不继续按样本增加规则 |
| 状态与交付 | 账户隔离、版本、出处、编辑、复核、导出及兼容读取 | 已有主题与版本基础；统一各阶段产物和状态的版本化表达，旧版本保留、未知状态不补造 |

外部来源和模型供应商属于可替换适配器，不能直接决定系统权限、产品范围或财务正确性；FRED 的使用限制照旧。各层应传递版本化的任务、来源、证据、计算、主张和运行状态，不以聊天上下文或自然语言报错作为唯一状态来源。用户数据和旧功能保持兼容，FM 的最终定位仍待评估。

## 三、整合次序

1. **统一执行边界**：从 API 入口提取任务和来源策略，再按阶段抽取协调职责；统一权限、预算、错误和状态表达。保留原入口与版本兼容，避免一次性替换整个系统。
2. **贯通研究闭环**：让规划、授权取证、证据和计算、主张与反方审查通过共同的运行上下文协作；结果与缺口可以保存、恢复查看、编辑和导出。默认任务只执行必要步骤。
3. **治理历史规则**：按通用能力和真实风险梳理既有规则；保留仍需的保护，将规则逐步归入通用解析、检索、校验和审查边界。不围绕个别样本继续堆叠特例，不未经验证批量删除保护。
4. **统一交付与阶段收尾**：贯通工作区与版本、来源、计算和运行状态，检查失败和部分交付。待用户解除当前测试暂停后，在固定的多类型任务及故障场景上集中验证，并记录所有尚未满足的阶段出口；跳过人工验收不等于质量已通过。

阶段 C 的持续更新和阶段 D 的资产暴露不作为阶段 B 的补充功能。此顺序用于推进完整首次研究闭环，不把模块数量、提交次数或某个样本的通过视为完成标准。人工、工期、模型、供应商及数据覆盖不在缺乏证据时预设。

## 四、本次框架落地

将来源资格、时点与权限判断、运行来源摘要和选取记录归入独立来源策略模块；研究分析和运行入口复用同一边界，保持原有状态和接口。此工作只建立第一条模块边界，协调器、统一阶段契约和研究链路整合仍需建设。按用户当前指令未运行测试或模型实验，重构兼容性尚待集中验证。

## 五、共享运行预算边界

规划、首次生成、反方补充、缺口补充和模型复查共用 `ResearchExecutionBudget`，以相同语义判断调用次数、Token 预算与截止时间；缺口来源搜索也通过该边界判断次数和时间。规划仍为后续首次生成保留一次模型调用预算；已知使用量按实际报告计入，未知用量保守按调用上限计算。

预算策略只是协调层的准入判断，不替代已有全局额度预留、费用结算、取消、检查点或供应商适配。供应商费用无法事先确定时仍按原有策略处理，不视作零成本。现有 API 和历史运行记录保留；阶段编排与运行上下文尚未全部移出入口。本次结构变更未运行测试或模型实验，预算边界、并发和恢复语义尚待集中验证。

## 六、协调层的第一个阶段边界

将可选研究规划从 API 运行入口移入独立阶段处理器。该阶段接收明确的研究问题、范围、来源可用性、模型能力、共享预算、取消及调用预留/结算能力，返回计划、状态、用量、提示哈希与错误；不能自行扩大权限或启动其他工具。API 暂时继续负责接纳、来源发现、持久化和运行生命周期。后续生成、补充、审查和交付仍需按同一原则分离并整合，当前不把单个阶段抽取当作协调器完成。

该调整不依赖特定行业、公司或样本，既有调用次数和未知费用边界保留。按当前用户指令未运行测试和模型实验，兼容性、异常、取消和实际调用行为尚待集中验证。

## 七、首次分析的协调边界

首次分析与模型调用从入口移入同一协调模块：该阶段接收已选来源、时点、问题、计划、预算及明确的预留、结算与取消能力，返回研究结果、调用量、提示记录和失败信息。来源选择、模型输出核查、确定性计算和部分失败结果沿用现有实现；接口入口继续负责运行接纳、来源获取、持久化和检查点。模型能力限制不可用时，允许记录来源选取状态，但仍阻止无法执行预算控制的模型调用。

这使规划和首次分析具有明确阶段输入与输出，但并不表示补充取证、复查、统一运行上下文或交付编排已经完成。按用户要求尚未测试或运行模型实验，阶段行为、异常恢复和预算兼容性仍待集中验证。

## 八、共享研究运行上下文

规划和首次分析现在使用同一运行上下文，持有预算策略、调用计数、已报告用量和取消、预留、结算能力。成功预留后计数，结算时更新已知用量；任一环节用量未知时保留未知，后续预算判断继续保守估算。阶段只拿到明确授予的能力，不直接获得额外来源或工具权限。

反方、缺口补充和复查暂时仍由现有入口编排，沿用原有预算与检查点；下一步将它们接入共同上下文并统一阶段产物，避免同时维护两套状态。该改动尚未测试，特别是异常和结算竞态仍需后续集中验证。

## 九、补充和复查接入共享上下文

反方补充、证据缺口补充、合并复查及逐条复查的模型预留、调用计数和用量结算统一使用同一研究运行上下文。逐条复查在调用前需要保存检查点；若调用尚未发生且检查点失败或时间耗尽，释放预留并恢复计数。已有独立搜索预算、检查点、取消、来源权限及各阶段结果继续保留。用量未知保持未知，外部调用是否计费仍以供应商实际情况为准。

目前阶段处理与检查点编排仍部分留在 API 入口；共享上下文只统一这些模型调用的运行状态，不代表整个协调器或阶段 B 已完成。按用户当前要求没有运行测试或模型实验，取消、异常、并发和持久化边界需要后续集中验证。

## 十、研究成果处理边界

首次分析后的结构化观察值、计划子问题和结论审查准备归入研究成果处理模块；首次生成和补充后的结论均通过同一组来源、计算与证据处理函数。该模块只处理运行中已授权的资料快照，不执行网络或模型调用，也不把模型解释升级为事实。现有保护逻辑保留，后续再按通用能力和风险治理，不增加针对具体样本的新规则。

用户编辑版本、阶段检查点与最终交付尚未全部统一到同一成果契约；本次只是明确研究层边界。按用户要求没有执行测试、浏览器检查或模型实验，兼容性及质量仍待集中验证。

## 十一、统一成果审查入口

将用户编辑版本和自动研究的共用证据检查收敛到研究成果处理边界。调用方显式传入允许用于一般核查、跨来源比较和历史日期检查的不同资料集合，以及相应的已选片段；生成结果和用户编辑仍维持各自的权限与来源约束。数值、期间、引文、反方及差异提示沿用现有处理，不把检查结果当作独立事实证明。

版本创建、用户确认与导出仍由原有状态和交付边界负责，统一审查入口不表示所有阶段已经迁移。按用户要求未运行测试或模型实验，保存兼容性、权限隔离及已有提示的保持情况仍需集中验证。
