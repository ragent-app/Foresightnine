运行接纳在 `OperationStore.begin` 内按主题序列化；首次分析、反方、缺口补充和复查在阶段结果已提交、外部调用状态已结算时可保存续跑快照。`/continue` 重新核对账户、版本、来源权限、请求、模型和原预算，并对每个快照单次消费；原截止时间与累计用量沿用。外部调用状态不明、旧记录信息不足或当前版本不匹配时，不自动重放；`/recover` 在具备可恢复检查点时只交付已提交成果。工作区以服务端恢复资格区分可用操作。并非所有中断都产生安全快照。

本节为静态实现描述，尚未执行本轮测试或模型实验；不代表恢复、隔离或研究质量通过。下表保留此前架构基线，其关于不支持检查点续跑的描述为历史状态；以本节为准。阶段 C 事件和阶段 D 资产影响仍是后续方向。

## 产品与系统边界

产品是通用金融研究 Agent 工作台，不以某个行业、公司、来源或评估样本限定能力。阶段 B 的目标是从问题或授权资料出发，完成首次研究、来源和证据核查、计算、反方、部分交付与版本保存。持续更新属于阶段 C，持仓和资产影响属于阶段 D。

```text
用户问题、研究范围、资料权限与预算
                  ↓
研究协调：规划 → 来源发现和获取 → 分析与计算 → 缺口、反方及审查 → 交付
                  ↓
共享工具：来源策略 / 文档与结构化数据 / 确定性计算 / 模型与搜索适配器
                  ↓
研究状态：主题、资料、事实、主张、证据关系、运行快照与版本
                  ↓
工作区：查看阶段成果、核对来源、编辑与确认、重开和权限内导出
```

模型负责规划和解释；代码负责权限、预算、计算、状态和可追溯记录。外部材料与工具结果是不可信数据，不能授予权限或改变系统指令。来源线索不等于证据；引文定位、模型意见与独立核验是不同状态。流程概览只描述保存时的执行状态，缺少历史记录时标为未知。

## 接下来的整体工作

1. **完成协调与工具闭环**：把剩余阶段围绕统一任务、权限、预算、阶段产物及错误状态整合；保持现有 API 与历史版本兼容，不以拆分文件数量作为目标。

3. **贯通工作区与失败交付**：用户可以查看已保存成果、来源和待办，编辑后形成新版本并在许可内导出。失败、预算耗尽与取消保留可用成果；不能确定是否重复收费时明确提示。
4. **按阶段集中验证**：在用户解除当前测试暂停后，对 B01–B10、多个研究类型及故障、隔离、恢复场景进行相应验证，固定实验数据与预算。人工验收按用户要求跳过；缺失的独立质量证据不能因此视为通过。
