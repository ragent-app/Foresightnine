# 阶段 B 研究接口与恢复语义草案

状态：设计候选，未实现、未批准为现有 API。对应[阶段 B 规格](06-phase-b-spec.md)。最终名称与阈值待原型、来源许可和人工评估后确定；不要将以下路径写成当前已存在的服务。

## 接口与范围

以下以 `/v2/research` 为讨论用前缀；实际版本和兼容策略须在正式契约登记后确定。所有操作都需要服务端确认主体和对象归属；匿名私人研究只有在有可验证的隔离能力时才开放。读取、修改、导出以及重试使用同一访问边界。当前匿名用户共用 `anonymous` 主体，不能直接作为私人研究隔离保证。

| 操作 | 候选请求 | 结果和限制 |
| --- | --- | --- |
| 创建研究 | `POST /topics`：`question` 或 `source_ids` 至少一项，选填 `as_of`、`scope`、`asset_refs` | 返回 `topic_id`、初始版本和状态；无需资金、观点、评分、情景或 FM。身份不明或问题含糊时保留缺口或请求澄清。 |
| 读取主题与版本 | `GET /topics/{id}`、`GET /topics/{id}/versions/{version_id}` | 仅返回主体可见内容、版本和来源状态。不可访问和不存在均返回同一类不可枚举错误。 |
| 发起研究 | `POST /topics/{id}/runs`：输入版本、允许来源、时点、预算及幂等键 | 返回 `run_id`、状态、预算及已知缺口；请求中的来源范围须与服务端许可取交集。 |
| 查看或取消运行 | `GET /runs/{id}`、`POST /runs/{id}/cancel` | 显示可用进度和实际费用；取消防止继续调度，不能保证第三方已接收请求未执行或未计费。 |
| 从检查点续做 | `POST /runs/{id}/resume` | 已终止运行不复活：若存在验证过的检查点，以原运行和检查点为父项创建新运行；否则明确返回不可恢复和可保留结果。 |
| 复核与保存 | `POST /topics/{id}/versions`：父版本、用户编辑、确认或保留意见 | 采用乐观并发检查；旧版本不可覆盖，冲突时返回当前版本供重新合并。 |
| 导出 | `POST /topics/{id}/exports`：版本和格式 | 只导出有权访问及有权导出的内容；保留缺失/受限提示、来源定位和方法版本；禁止带出凭据。 |

这些接口只提出需要的行为；实现时应使用现有工程生成版本化 schema、类型和 OpenAPI，并验证旧 API 兼容。不得静默变更旧 `v1` 的语义、删除原数据或把旧模型推断标成已验证事实。

## 数据和不可变性

| 对象 | 约束与关键关联 |
| --- | --- |
| `topic` | `id`、`owner_id`、`question`、`scope`、`current_version_id`、创建/更新时间；公司、证券、交易所、币种和日历分别关联。 |
| `source` | `id`、`owner_id` 或授权公共范围、原始定位、内容哈希、事件/公开/获取/修订时间及各自未知状态、保存/展示/模型处理/导出权限、失败/过期状态；未获许可不默认允许。 |
| `fact` | `source_id` + 文内定位、值、单位、币种、财务期间、提取方式和核验状态；模型解释、用户私有资料、模拟值与可验证事实分别标识。 |
| `calculation` | 输入事实及其版本、公式标识与版本、单位、舍入、输出或具体错误；不支持、零分母、单位不可比等不能返回看似有效的数值。 |
| `claim` | 内容、类别、支持和反对 `fact`/`calculation` 引用、未知项、状态；引用存在不等于引用足以支持主张。 |
| `version` | `id`、`topic_id`、父版本、内容哈希、作者、创建时间、用户确认与保留意见。完整快照或可重建事件序列必须能够还原历史内容；存储行的递增版本号本身不足以证明历史留存。 |
| `run` | `id`、`owner_id`、输入版本/资料快照、工具范围、状态、检查点、预算、实际用量、错误、关联父运行、创建及结束时间。记录不得含访问令牌、密钥或无权保存的原文。 |

来源中的时间不可以用单个 `timestamp` 代替：至少区分事件发生、信息公开、系统获取和修订；无法确认时保存未知值和原因。会计期间、单位、币种、价格调整和公司证券身份均需显式校验。任一来源故障应作为缺口，而非以默认零值、硬编码数值或模拟数据补成真实事实。

## 运行状态与预算

候选状态及合法迁移：

```text
queued → running → completed
                 → partial
                 → failed
queued/running → cancel_requested → cancelled
```

`completed` 表示该次被接受范围的步骤完成，并非声明事实已被人工确认；`partial` 表示预算、来源或工具约束下保存了可交付内容及缺口。终态不可被覆盖。收到取消时要先持久化取消请求，阻止新步骤；正在执行的外部请求能否中止和是否计费分别记录。竞态中若结果先被持久化，应显示真实终态；不声称取消必然避免费用。

运行启动前检查 `max_calls`、`max_elapsed_seconds`、`max_cost`（币种明确）及工具范围；数值由经过人工基线的实验登记或部署配置决定，这里不预设上线额度。每个外部调用应在发送前执行并发安全的预算预留，记录提供方报告的用量/费用、不可确认的结算状态、重试与超时。费用或使用量未知时明确显示未知，不记作零；不能凭进程重启认为未发生外部调用。预算耗尽返回已保存结果和未完成步骤，不生成虚构结论。

同一主体、操作路径和幂等键绑定规范化请求内容：重复相同请求返回同一操作，不重复提交；同键不同内容返回冲突。检查点仅能在输入快照、权限及方法版本仍一致时恢复；第三方调用结果不确定时先核对回执或标为需处理，不能盲目重放并宣称不会重复收费。已确认结论的更新通过新版本和用户确认实现，而非后台覆盖。

## 错误与界面行为

| 类别 | 结果示例 | 界面/恢复要求 |
| --- | --- | --- |
| 参数或口径错误 | `invalid_request`、`unit_mismatch`、`zero_denominator` | 指明字段或公式缺口，允许修正；不输出假数字。 |
| 身份和权限 | `not_found`、`source_permission_unknown` | 不泄露其他主体是否存在；权限未知时限制读取、模型处理或导出。 |
| 外部来源 | `unavailable`、`rate_limited`、`stale`、`not_yet_public` | 显示来源状态、时点与影响；重试规则和次数受预算限制，不回退到模拟。 |
| 运行控制 | `budget_exhausted`、`cancelled`、`recovery_unavailable` | 保存可交付片段与缺口；可恢复性和可能费用分别说明。 |
| 写入并发 | `version_conflict`、`idempotency_conflict` | 保留两个已有版本或请求信息；让用户重新读取、比较或明确另起操作。 |

这些错误名是候选语义，不是已实现契约；公开错误不包含凭据、其他用户内容、内部主机或完整外部原文。

## 用现有证据检查设计

1. 首次研究：给定 2023 财年题目及允许来源，保存事实、计算、反方与未知；只输入问题即可开始。2024 文档在这一轮不可用。
2. 来源故障：注入超时、失效和预算耗尽，验证部分结果、未完成步骤以及无模拟回退；通过与“成功但无重要变化”区分。
3. 并发与恢复：使用同一请求重复提交、同键不同内容、取消与外部提供方结果竞态，以及进程重启和无法确认的回执；逐项检查写入、费用和状态。
4. 权限：两个账户及匿名主体分别尝试读、写、搜索和导出另一个主体的数据；包括已知对象 ID、旧记录和导出文件。
5. 兼容与回滚：在副本上演练旧研究读取、迁移、核对和恢复；生产数据、第三方服务及用户原件不能由草案或合成测试代替。

以上检查是 B 的候选验收用例，不声称现有代码已经通过。性能、准确率及成本门槛在 A4 的真实人工基线之后、正式实验之前登记。
