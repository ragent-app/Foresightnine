# 网络传输的整体等待预算

原有网络连接超时在 DNS 完成后才开始计时，且缓慢接收数据时单次套接字超时可能被不断刷新。网络传输现从启动前计算截止时间，在受限后台线程中完成 DNS、TLS、请求和读取；调用方等待至截止时间后返回超时并尝试中断套接字。超时后 DNS 等系统调用不一定能立即终止，因此每个进程最多保留 16 个传输槽，未结束的调用继续占用槽，容量耗尽时快速失败。已提交的外部请求仍可能被服务商处理或收费；不能保证远端取消，也不能把未知费用记为零。线程调度及结果解码等开销不构成实时系统级时限保证。

保留固定主机及 DNS 校验、连接到已校验地址、TLS、响应大小限制、不跟随重定向以及文本严格 UTF-8 校验。结构化研究生成仍不对结果不明的 POST 隐式重试，旧调用的既有重试策略不因本次修改改变。测试覆盖 DNS 挂起、响应读取挂起、后台调用占用槽时的容量限制、二进制与文本边界，以及原有模型、搜索和研究调用。2026-11-13 单次 BEA HTML 直连返回相同哈希 `10970e0f520e4571372e2f5e5d121f92ad1448e7871c26297f46cd8bdc3cee76`，耗时 1.562 秒；无模型调用。此检查不穷举生产网络故障。
