# 复查批次编号与原主张映射

168 号复查提交了原主张索引 1–5，但供应商返回 0–4，包含未提交索引；原结果按规则被拒绝。不能确认模型为何返回这些编号，也不能将其旧响应事后重新映射。

v22 在每次新复查提示中按本批次顺序使用连续编号 0、1、2……；服务端保存的 `support_review_indexes` 按同一顺序记录对应的原主张索引。模型返回必须是本批次编号且无重复，校验通过后才映射回原主张；来源片段、跳过原因和模型遗漏仍使用原主张索引。空响应、越界、重复和无效结构继续拒绝，部分有效响应仅保留已返回判断，未覆盖项仍标记遗漏。该机制不能保证模型对指定文本作出正确判断。

复查调用前的生成检查点现保存方法标识、提示哈希、索引映射及原文片段范围；已中断或历史运行不改写。测试覆盖首项或中间项被跳过、结果逆序、部分结果、重复及越界编号、正确写回原主张和检查点审计数据。相关研究运行和复查 API 测试通过；没有新的模型调用，也没有更改 168 号原始响应和失败结果。阶段 B 仍需真实模型验证和独立质量评估。
