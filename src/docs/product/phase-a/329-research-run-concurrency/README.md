# 329：同一研究主题的并发运行控制

同一主题如果以不同请求标识同时启动多次研究，即使最终版本写入使用乐观并发控制，也可能先重复调用模型或搜索。服务端现在在异步运行接纳事务内检查该账户、该主题已有的待执行或执行中研究；若有正在执行的任务，拒绝接纳新的不同请求。已有幂等重放仍返回原收据。PostgreSQL 使用主题事务级锁协调进程，内存适配器使用运行仓库的进程内接纳锁；不同主题互不约束。

重新打开研究时，界面优先跟踪仍在执行的任务。已跟踪运行结束后，重新查看是否还有历史并发运行；接到冲突时刷新主题与运行状态。网络失败仍保留同一次请求标识，以便安全重试。已有并发任务不会被取消；失联工作由既有租约恢复机制判定终态。已取消不保证第三方调用立即停止或未产生费用，不能推断外部账单。

用户当前要求暂不测试，因此尚未验证并发竞态、跨进程锁、租约回收、幂等重试与界面行为；不要视为阶段 B 通过。
