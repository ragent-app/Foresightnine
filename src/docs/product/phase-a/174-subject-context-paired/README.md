# 必要主体上下文：配对诊断预登记

使用两条 171 号已见真实资料主张，另加入两条明确标为虚构的合成主体测试：同一段“River 的收入增长 5%”分别用于判断 River 和母公司 Harbor Labs 的收入。合成资料只存在本地实验提示中，不进入产品资料库或真实研究证据。保留两条真实主张及其引文，以检查先前发现的缺证情形。

固定四条主张、引文、系统提示、模型与参数；唯一主动变量是引文前后的可选上下文。对照提供完整相邻上下文，候选移除可选上下文，但对合成主体的两条引文保留必要的 `River's` 作为解释上下文；并非把它作为被引用事实。两份提示和合成资料在调用前固定哈希。该实验直接构造提示，用于比较模型行为，不模拟完整 API，不验证规则能覆盖所有主体。

每条件最多一次调用，先对照后候选，输入上限 6000、输出上限 4000、每次预留 10000 Token、超时 60 秒，总计最多两次及 20000 Token，不搜索、不重试。异常、状态或用量未知时停止。此前已知累计 194626 Token，另有未知历史用量；模型内部版本和美元费用未知。

预期：储蓄率主张应支持；另一真实主张缺少名义增长的引文，应判不支持或不确定；River 主张应支持；将 River 的数值归于 Harbor Labs 的主张不得判支持。四项分别记录，不因部分通过而认定总体通过。模型对上下文的解释可能有歧义，该已知合成样本不能证明生产泛化或 B 阶段质量验收。

## 结果

两次调用均确定完成，完整上下文与仅保留必要主体上下文分别报告 909、622 Token，合计 1531；已知累计 196157 Token，另有历史未知用量及未知美元费用。两项返回的四个编号均有效。两种条件下，模型均支持储蓄率和 River 主张，且均未支持把 River 数值归于 Harbor 的主张；这些是合成样本上的有限检查，不证明所有实体可正确识别。

两种条件均错误地把缺少名义消费增长引文的真实资料主张判为 `supports`。这与 172 号单次仅引文条件的 `uncertain` 不同；本次同时改变了批次中的其他主张和合成材料，不能据此归因于某个因素。减少上下文并不能单独保证模型逐条判断引用支持；批次中其他文字、模型随机性和未识别的语义因素仍可能影响结果。未据此更改默认复查方式或历史评分，阶段 B 质量验收尚未通过。
