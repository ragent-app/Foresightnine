# 逐条证据复查的执行与恢复

阶段 B 为可选的证据支持性复查增加逐条模式，原批量模式仍为默认。逐条模式每次只向模型提交一个待核查主张及其允许使用的原文；批次编号和研究主张编号在服务端映射。反方与支持主张按准备阶段的顺序交替处理。界面允许选择模式并设置包括首次生成在内的总模型调用上限，限制为 2–10 次；Token、时间和账户预算仍分别生效。未知实际用量按完整单次预留控制后续调用。金额费用未知时不假称已知。

首次生成后、每次复查请求前及每次成功处理后保存版本检查点；未启动、进行中、已完成、失败及因预算未启动的项目分别记录。请求前的“进行中”是保守状态，不能证明请求已到供应商。进程中断或取消后保留已提交的检查点，不自动重发未知结果的外部请求；未结算预留需按现有账务规则处理。用户在运行期间修改研究版本时，后续模型结果不会覆盖用户修改。保存检查点和执行外部调用之间仍存在短暂间隙，不能保证外部费用一定可知，也不能从中断位置自动续跑。

针对调用次数、Token 限额、无效响应、取消、并发用户编辑以及逐次检查点保存添加 API 测试；使用临时 PostgreSQL 和独立进程测试第二次复查中断，确认第一次结果保留、第二次显示进行中且预留保持未结算，重放不重复调用。网页的逐条模式、调用上限和部分完成提示以本地测试替身进行过桌面及移动端浏览器检查。生成契约、相关 API 测试、Web 类型检查、测试及生产构建另行执行；这些检查不验证真实模型的语义准确性。

本次实现未调用真实模型。175 号非盲配对诊断中逐条结果优于批量只是一次观察，不能证明该模式总体更准确；模型复查仍不是独立核验。阶段 B 的语义支持、反方充分性和正式质量评估仍需继续验证，不能据此宣布阶段完成。
