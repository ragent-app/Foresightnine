# 反方引用提示词受控探索

目的：检查反方模板中的空引用是否可能妨碍使用已有反证。两次调用固定同一模型及供应商配置、系统提示、问题、来源、权限、提取、片段预算与超时；唯一更改是研究输出提示中反方引用示例和“有证据则引用、缺证列入限制”的说明。调用顺序固定为旧提示、新提示，每个一次，无 POST 重试；第一项状态不明或失败则停止。单次上限由供应商配置和 60 秒超时控制，最多两次调用；金额费用未知。

输入是从 [Tesla 2024 年 10-K](https://www.sec.gov/Archives/edgar/data/1318605/000162828025003063/tsla-20241231.htm)整理的 2023/2024 总收入和毛利润四项事实，单位为百万美元，不是完整原始文件。提供正反两个指标，不构成独立资料或历史版本验收。问题与参考值对开发者可见；一次配对探索不能估计模型总体质量、证明因果或代替独立测试。

调用前固定输入、运行程序、评分程序和 `manifest.json` 的散列。预先定义的机械条件要求一条已定位反方引文同时包含 17660 与 17450 两项毛利润数值；这只说明定位到了相关数字，不证明反方文字、财务口径或全部主张的语义正确。无论结果如何保留两项输出与原评分，不针对这组数据重复调参或重新调用。

结果：旧提示未生成带定位引用的反方，预登记机械条件失败；新提示的反方引用包含两年的毛利润数字，机械条件通过。两次分别报告 1195 和 1493 Token，模型标识为 `glm-5.3-flash`，金额费用未知。新提示结果将收入和毛利润的方向分别引用，但将“盈利质量恶化”作为较宽泛的推论，资料不足以独立证明该表述；降价换量也仅是假设。机械通过不证明语义充分或反方整体充分。

两次均使用同一段 165 字符来源、同一系统提示和同一供应商配置。为比较旧提示，实验包装器在向供应商发送前还原旧字段，因此旧提示实际发送哈希以输出的 `provider_prompt_sha256` 为准；`result.prompt_sha256` 是包装器修改前的新提示哈希，不能用于识别旧提示。此包装器只用于本次探索，正常产品运行不进行该替换。本次未使用完整 API、账单账本或独立盲测，不能当作 B04/B09 整体验收。

实验程序未在发送时单独保存生成参数；事后使用相同提交与容器配置重建请求体，得到 `max_tokens=4000`、`response_format=json_object`、`thinking=enabled`、`reasoning_effort=low`、`do_sample=false`，本地输入上限 3000 Token、超时 60 秒。此为事后重建而非线上逐次请求抓包；模型供应商内部版本和实际货币成本不可锁定。
