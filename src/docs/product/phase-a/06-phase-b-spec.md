## 1. 用户任务与边界

用户输入一个问题、来源链接或已授权的资料，可选择对象、时间和期望交付；系统在需要时询问缺失约束。普通事实核验、财报比较或宏观解读无需输入观点、资金，也不强制经过 Challenge、情景或 FM。用户可以检查来源、计算、反证和未知项，修改研究内容并导出经标识的结果。数据和权利不足时交付已完成部分并明确缺口。

实现应对任意行业、公司、市场和证券提供可扩展身份及工具接口；首批承诺以实际数据与测试证据为准。候选首条样本为 Microsoft 2023 财年研究和 2024 财年更新回放；这仅是样本，不是固定名单或未来信息安全证明。其他行业、宏观及故障任务用于评估泛化。真实下单、托管和全市场实时信号不在首版。

## 2. Web 流程

1. 创建研究：问题或资料至少一项；明确时间范围、资料可用性，未填写的金融前提不自动假定。
2. 计划与执行：展示任务范围、来源和预算，显示进行中、部分完成、完成、失败或取消；用户可取消，系统在能力允许时恢复。
3. 复核：展示每项主张的来源定位、日期与状态，计算输入和公式、反方、冲突和未知项。区分事实、计算、模型解释、用户资料与模拟。
4. 用户确认：用户可修改、接受或保留异议；已有核心判断若被后续修改需展示差异并记录确认。研究完成不要求得分或购买配置。
5. 保存与导出：主题、材料、计算及确认独立于聊天保存；导出包含版本、截至时间、引用、口径、缺口和标识，在权限不足时排除受限原文并提示。

## 3. 核心对象与版本接口草案

所有对象有 schema 版本、唯一 ID、归属账户、创建/更新时间和可追溯关联。授权及历史记录不能仅依赖客户端；公司与证券、交易所、币种和交易日历分别建模。

| 对象 | 必要字段及约束 |
| --- | --- |
| ResearchTopic | 标题、用户问题、范围、对象、状态、当前版本和 owner；不要求资金。 |
| SourceDocument | 提供方、原始 URL 或用户资料归属、标题、内容哈希或定位、事件/公开/获取/修订时间、访问及保存/展示/导出权限、状态；必要时间未知时显式为空并标记。 |
| Evidence | 资料和具体定位、原文范围或许可内摘录、提取事实与期间/单位/币种、核验状态、关联主张；私有和模型来源不能标为公开已验证事实。 |
| Calculation | 输入事实 ID 与值、公式 ID/版本、单位及精度、输出与错误；使用确定性代码计算而非依赖语言模型算术。 |
| Claim / Review | 主张、事实与推断类型、支持/反对证据、冲突、未知、用户编辑及确认/保留意见，指向研究版本。 |
| ResearchVersion | 不可变内容或可重建快照、父版本、变更来源、作者与确认状态；并发版本号不单独替代历史。 |
| ResearchRun | 用户与主题、输入快照、工具权限、步骤与状态、预算/用量、超时、幂等键、取消、错误和可恢复点；不保存凭据。 |
| Deliverable | 对应研究版本、格式、生成时间、引用/数据时点和许可限制；无权限内容不可导出。 |

以上是拟议契约而非当前 API；实施前新增向后兼容的版本化接口与生成类型、迁移脚本和测试。现有 `v1` thesis/challenge/worldline/FM 的读取和计算边界应保持，转换仅在保留来源、原记录和所有权前提下执行；不将旧模型推断升级为事实。提供受控备份及可演练恢复，迁移前补齐实际数据库与用户资料清单。

接口、状态、预算和失败恢复的进一步草案见[研究接口与恢复语义](06b-phase-b-contract-draft.md)；其中路径和字段是设计候选，尚不是现有实现或已批准的新 API。

## 4. 工具与运行边界

| 工具 | 输入 | 输出及失败语义 |
| --- | --- | --- |
| 来源获取 | 授权来源、检索范围、截止时点、预算 | 资料定位、事件/公开/获取/修订时间、权限、哈希和状态；限流、超时、失效、无权限分别可见，不用模拟填充 |
| 身份识别 | 公司名称、证券标识、市场和时点 | 候选身份与来源；歧义时保留候选并请求澄清，不默认单一市场 |
| 事实提取 | 可用资料及问题 | 事实、源定位、期间、单位、币种、提取方法及核验状态；外部文本不得授予权限或改变系统指令 |
| 确定性计算 | 有版本的公式、引用事实、单位和精度 | 输入、公式、结果和错误；零分母、单位不一致或缺失时拒绝误导性数值 |
| 证据检查 | 主张、资料、时间范围 | 支持、反对、冲突和缺口；引用存在与真正支持分别检查 |
| 交付 | 用户可见研究版本和格式 | 受许可约束的文件及状态；禁止泄露凭据、其他账户数据与未授权原文 |

运行时应以服务端控制数据范围、工具调用、花费、时间、重试和并发；每步记录输入输出与状态并提供取消、幂等与可验证恢复。预算耗尽时保留已完成结果，区分失败、部分完成和没有发现变化。外部文件及工具输出是数据，不是新的系统指令。

## 7. 2026-11-13 系统性改进实施规格

### 7.1 目标及已知缺陷

保留以问题或资料开始的通用金融研究入口，完成首次研究的计划、取证、计算、审查、部分交付与版本闭环。当前真实研究已经暴露复合主张引用不完整、反方未回应原判断、以部分摘录概括全文、表格期间/币种/指标错配及模型复查不可靠等问题；具体事实、后续修复与未完成项参见[当前验收记录](208-stage-b-current-audit.md)。不能因实施本节而认定 B02、B04、B09 已通过。

### 7.2 面向任务和证据的契约

1. 将用户问题组织为有界研究任务和子问题，记录范围、截止时间、所需资料、工具权限、预算、状态和缺口；简单任务可以不执行不必要步骤。任务样本不是市场或行业限制。
2. 资料与证据保存来源、归属、许可、原文或获准摘录、定位、文档及表格结构、内容版本、事件/公开/获取/修订时间和已读范围；不完整资料不能支持全文缺失断言。
3. 金融事实保存对象、指标、期间、数值、单位、币种、会计或调整口径、来源和待核查状态；计算保存事实引用、公式版本、精度、结果及错误。事实提取和计算结果与模型解释分别保存。
4. 主张保存支持和反对证据、相关计算、冲突和未知；反方关联其回应的主张及自身来源。原文定位、语义支持、模型审查和用户确认是不同状态。
5. 研究版本保存上述对象及运行快照，保持不可变历史或可重建历史；兼容已有版本、资料权限、导出约束和用户修改。

接口与持久化结构在实现时具体设计并版本化。不得仅因字段齐备就判定引用语义正确。

### 7.3 研究执行、工具和审查

研究协调器在受控的工具和资料范围内执行“规划 → 取证 → 形成事实、计算和主张 → 审查缺口/冲突 → 预算内补充 → 交付”，并记录每个子任务的来源、状态与剩余缺口。来源发现、文档/表格读取、金融数据和确定性计算通过有明确输入、输出、来源、时间、权限和失败行为的工具提供；模型供应商和数据供应商保持可替换。

检索以研究问题、实体、指标、期间和文档结构为依据，组合关键词、语义和上下文，保留反证及不同来源；不能把转载计成独立证据。对部分材料只陈述已查看范围，资料不可用、过期与无结果分别表示。区分事件发生、公开、获取和修订时间；不将 FRED 当作已获许可的 LLM 输入。

确定性工具检查公式、单位、币种、期间、分母和精度；不因数值共现就确认指标含义。模型辅助审查逐项核对引文定位、语义覆盖、实体期间方向、冲突及反方相关性；模型意见是意见，不得将未核验结论自动升级为事实。

运行中执行服务端预算预留、调用计数、超时、取消、幂等和检查点恢复；预算耗尽交付部分成果并说明缺口。外部调用结果或费用未知时记录未知，不保证重试不会产生重复费用；来源和输出遵守账户隔离及许可边界。

### 7.4 工作区及交付

用户能查看研究计划、步骤和来源、单条结论及其证据、计算、反方和未知；比较任务按对象和问题展示可追溯的条目，保留缺失与口径差异。用户能够保存、编辑、确认、保留异议、重开并按权限导出。持续监控、变化收件箱、事件去重、资产暴露与持仓模拟仍分别属于 C 和 D，不纳入 B 的完成声明。

### 7.5 迁移与验证纪律

复用当前研究工作区、来源/版本管理、确定性计算、引文定位和运行控制；通过版本化契约逐步接入新结构。保留已有特殊规则作为风险提示，避免继续按单个样本增加特例；不得未经验证整体删除已有保护。保留旧功能、原始材料、用户数据和旧版本，FM 最终产品定位仍待收敛。

用户于 2026-11-13 指示先完成实现并暂时禁止测试和模型实验，直到用户后续解除。人工验收跳过，不以等待用户参与作为阻塞；尚未获得的独立质量证据、数据授权和现有真实任务失败照实记录，不因跳过而视为通过。上方 B01–B10 保持阶段出口条件，用户解除暂停后再按届时授权集中处理验证；不得在实验后移动阈值。LLM 实验如获允许，固定任务、数据、权限、提示词、支持参数及预算，一次只改变一个主要因素，保留用量和结果。
