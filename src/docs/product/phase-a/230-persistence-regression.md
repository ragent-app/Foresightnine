# 财报资料与复核状态的持久化检查

在一次性 PostgreSQL 16 和 Redis 7 容器中运行当前实现的持久化与恢复检查，全部 **14 项通过**。其中新增跨进程检查：通过 API 上传合成 HTML 财报、生成两条带表格标记的候选事实、分别记录用户核对、计算 25.00% 增长率；启动另一个进程后，原始 HTML 字节、来源归属、核对记录和计算结果保持一致，其他账户不能读取来源或主题。测试账户和临时容器已清理。

其余检查覆盖研究生成前后、复查和结果写入边界的进程中断恢复、PDF 重新提取幂等、来源筛选、现有备份恢复演练及 Redis 连通性。备份演练覆盖的是其既有合成研究记录；新增 HTML 及表格确认经过的是跨进程数据库检查，不能称为已单独完成 HTML 备份演练。所有模型响应均为测试桩；这些检查不代表生产备份策略、外部服务费用恢复或真实研究质量已经验证。

此前 225 号全量 API 回归中的外部服务跳过项已有针对性验证，但 229 号解析修改及本次新增测试尚未包含在一次新的全量 API 回归中，阶段结束时仍需完成。用户明确要求跳过人工验收，本次未要求用户操作。
