# US Earnings Buy-Side Squad — End-to-End Live-LLM Execution Audit & Hardening Plan

**Date:** 2026-11-24  
**Triggering Incident:** Real production failure on `topic_33f4240706c8458fa78b4c273d2c9c3d` (`operation:ebba1dc581e1725a3715377c`) — Stage 1 `ResearchDispatchPlan` Pydantic `ValidationError` (`extra_forbidden` / missing `tasks`), while `GET /v2/research/topics/{topic_id}/earnings-squad/dossier` returned HTTP `200` with `status="failed"` and `dossier=null`.  
**Scope:** Full line-by-line audit of the live-LLM execution path across wire protocols, `_AccountSlotModelRunner`, Stage 0–3B prompts/payloads, tool schemas & `FinToolboxToolRunner`, structured output parsing & repair, Stage 0→3 data/ID flow & user uploads, persistence/restart recovery/SSE, and frontend error UX — followed by a prioritized `P0 / P1 / P2` remediation plan and stress-test matrix.

## Executive Summary & Incident Root-Cause Trace

All existing Phase A2/A4 tests passed (`145/145`) because they exercised `CallableSlotModelRunner` / `DictSlotModelRunner` returning pre-constructed Python `BaseModel` instances (`test_research_earnings_squad.py`, `test_a2_squad_api_and_export.py`), plus a single synthetic `_AccountSlotModelRunner` test with a `FakeWireProvider` (`test_a2_squad_api_and_export.py:1388-1444`). None of the suite ever ran a messy real LLM through `_AccountSlotModelRunner` → wire provider → prompt → Pydantic parser → `FinToolboxToolRunner` → UI error path.

Tracing `topic_33f4240706c8458fa78b4c273d2c9c3d` (`operation:ebba1dc581e1725a3715377c`) reveals a **compound failure** across five layers:

1. **Wire schema drop (`main.py:5107-5112`, `model_protocol.py:80-87`):** Stage 1 (`research_earnings_squad.py:3335-3336`) sets `response_schema_name="ResearchDispatchPlan"` and `response_schema=ResearchDispatchPlan.model_json_schema()` on `SlotModelRequest`. `_AccountSlotModelRunner.invoke` discards both fields completely and does not even send `response_format={"type": "json_object"}`.
2. **Underspecified Stage 1 prompt (`research_earnings_squad.py:3290-3322`):** The Lead system prompt is 4 sentences mentioning `"ResearchDispatchPlan JSON"` and `"1-3 read-only WorkerTask items"`, with **zero** field names, **zero** nested `WorkerTask` schema, **zero** enum lists, **zero** `WORKER_ALLOWED_TOOLS` constraints, **zero** `extra="forbid"` warning, and **zero** JSON example.
3. **Zero normalization & zero repair retries (`research_earnings_squad.py:4435-4439`):** `_parse_model_output` calls `json.loads` and immediately validates against `_FrozenContract` (`extra="forbid"`, `research_earnings_squad.py:290-291`). Any alias (`worker_tasks` instead of `tasks`, `role` instead of `worker_role`), markdown prose wrapper, or commentary key (`summary`, `reasoning`, `ticker`) causes an immediate fatal `ValidationError`.
4. **Broken multi-turn repair plumbing (`main.py:5089-5106`):** Even if Stage 1 attempted a repair retry, `_AccountSlotModelRunner.invoke` ignores all `role == "user"` follow-up messages when `turn_index > 0`, and emits an empty `tool_result` user message on Anthropic Messages (`anthropic_messages.py:207-211`) causing HTTP 400.
5. **Broken UI failure rendering (`main.py:5646-5648, 5934-5973`, `TopicPage.tsx:209-213, 1226, 1281-1283`):** Backend persists the raw English Pydantic `str(exc)` in `EARNINGS_SQUAD_STATES.error` and returns HTTP 200 on `/dossier` with `status="failed"`. Frontend simultaneously renders **both** the legacy `<InterruptedTurn>` (`orphanRun` ignores `showSquadWorkspace`) and the raw English Pydantic traceback in `<span className="inline-error">`, with **no Chinese error translation** and **no retry / resume-from-checkpoint action**.

Even if Stage 1 had succeeded, real-LLM execution would still fail immediately downstream due to:
- **Anthropic Messages total breakage (`main.py:5116-5117`):** `AnthropicMessagesProvider` returns `message["content"]` as `list[dict]`, so `isinstance(raw_content, str)` returns `None` on every single call.
- **Personal slot overrides blocked (`main.py:5207-5216`):** `_build_squad_slot_provider` omits `tools_verified` and `generation_parameters`, triggering `provider_configuration_invalid` on `OpenAICompatibleLlmProvider` (`openai_compatible.py:1667`) and `OpenAIResponsesProvider` (`openai_responses.py:196`).
- **3 analytical tools completely unwired (`research_earnings_squad.py:1444-1446`):** `earnings_quality_diagnostics`, `guidance_and_nongaap_reconciler`, and `valuation_and_implied_expectations` are in `WORKER_ALLOWED_TOOLS` (`:109-139`) but do not exist on `FinDataToolbox`, always returning `tool_not_wired`.
- **Stage 0 prefetched sources invisible to Workers (`research_earnings_squad.py:3118-3168`, `main.py:5397`):** Stage 0 creates `src_8k_release_*`, `src_sec_sections_*`, `src_transcript_*` in `source_texts`, never adding them to `FinToolboxToolRunner._source_by_id`, so every `read_sources`/`search_source`/`outline_source` call on a Stage 0 source returns `source_not_found`.
- **Worker turn-limit cliff (`research_earnings_squad.py:3920-3922`):** If a Worker requests a tool on `turn_idx == soft_turn_limit - 1`, it immediately `break`s without a final `tools=[]` synthesis turn, discarding all gathered evidence.
- **20s non-streaming timeouts & zero 429 retries (`openai_compatible.py:280`, `main.py:905, 5113`):** Stage 2 parallel workers burst 3 concurrent non-streaming HTTP calls with 20s timeout and zero retry/backoff on `429`/`5xx`, while `cancel_event`, remaining budget deadline, and `max_output_tokens` are never forwarded to `adapter.complete_turn`.

#### 1.1 Dropped `response_schema` / `response_schema_name`
- `research_earnings_squad.py:1276-1277`: `SlotModelRequest` carries `response_schema_name: str | None` and `response_schema: dict[str, Any] | None`, populated by Stage 1 (`:3335-3336`), Steering (`:3727-3728`), Stage 2 (`:3877-3878`), Stage 2.5 (`:4091-4092`), and Stage 3A (`:4225-4226`).
- `model_protocol.py:80-87`: `ModelTurnInput` defines only `(system, user, tools, history, tail_note, user_instructions)` — it has **no** `response_schema`, `response_schema_name`, or `response_format` attribute.
- `main.py:5107-5112`: `_AccountSlotModelRunner.invoke` constructs `ModelTurnInput(system=..., user=..., tools=tool_defs, history=tuple(history))` and silently drops `mreq.response_schema` and `mreq.response_schema_name`.
- `openai_compatible.py:1671-1700` (`_complete`), `openai_responses.py:171-183` (`_wire`), `anthropic_messages.py:243-263` (`_wire`): None of the three wire providers emit `response_format` or `text.format` during `complete_turn`. (By contrast, `OpenAICompatibleLlmProvider._request_body` at `openai_compatible.py:1466-1477` + `provider_capabilities.py:252-263` `wire_contract` already exist for `generate_structured`, but are unused here.)
- **Schema dialect caveat (`provider_capabilities.py:216-250`):** `_strict_schema` rejects any non-required property whose `default` is not `None` (line `244`). All squad contracts (`ResearchDispatchPlan`, `WorkerTask`, `EvidenceCardBatch`, `Stage25ReviewDecision`, `BearCaseBatch`, `SteeringImpactDecision`) use non-null defaults like `default="earnings_review"`, `default=4`, and `default_factory=list`. Furthermore, `research_profile` for personal accounts (`provider_capabilities.py:132`) hard-sets `mode="json_object"`. Therefore, wire enforcement cannot blindly invoke `_strict_schema(..., strict=True)` without schema normalization or `json_object` fallback; and for Stage 2 Workers (`tools` non-empty), sending `response_format` alongside `tools` is rejected by several OpenAI-compatible proxies (and prevents tool calling if `tool_choice` is forced), so `response_format={"type": "json_object"}` should only be applied when `tools=[]` (including Stage 1, 2.5, 3A, Steering, and the final `tools=[]` wrap-up turn / repair retries of Stage 2).

  - `anthropic_messages.py:207-211`: appends `{"role": "user", "content": []}` → **HTTP 400 invalid request** (`messages.X.content: empty list`).

  - `openai_responses.py:164-167`: renders `[user(init), *assistant_output]` with **no** trailing user message.
- **Bug C (`ModelTurnExchange` assumes tool calls only):** `model_protocol.py:74-77` has `assistant: ModelAssistantContinuation` and `results: tuple[ModelToolResult, ...]` with no `user_followup: str | None` field, forcing non-tool multi-turn retries to either add `user_followup` on `ModelTurnExchange` or use `tail_note` (carefully, because `anthropic_messages.py:215-218` mutates `messages[-1]["content"]`, which crashes/produces invalid alternating roles if `results_content` is skipped!).

#### 1.4 Concurrency & Thread-Safety Under Stage 2 Parallel Workers
- **`_AccountSlotModelRunner._turns` key collision & steering race (`main.py:5050, 5079-5115`):** `_turns` is keyed only by `(mreq.stage, mreq.role)`. When mid-run steering cancels an in-flight worker (`research_earnings_squad.py:3518-3530`) and immediately re-dispatches the same `worker_role` in `stage_2_workers` (`:3561`), the new thread starts at `turn_index=0` while the cancelled thread may still be inside `adapter.complete_turn(turn)` (`main.py:5113`). When the old thread returns, line `5115` acquires `self._lock` and overwrites `self._turns[(stage, role)]` with the stale response! Fix: key `_turns` by `(mreq.stage, mreq.role, task_or_conversation_id)` (add `conversation_id` / `task_id` to `SlotModelRequest`) or make `SlotModelRequest.messages` self-contained alongside an opaque continuation map keyed per conversation.
- **Shared provider instances (`main.py:5364`):** All 3 Stage 2 threads share `default_provider=primary_provider` and `_TRANSPORT_SLOTS = BoundedSemaphore(16)` (`openai_compatible.py:612`). `OpenAICompatibleLlmProvider` settings/policy are immutable (`@dataclass(frozen=True)`), and `_default_transport` opens a new `HTTPConnection` per call (thread-safe); `OpenAIResponsesProvider.stream_refused` (`openai_responses.py:153, 227`) is unsynchronized mutable state (benign boolean latch, though unused when `on_stream_event=None`). Note `main.py:3441` mutates `provider.policy` on legacy path if ever shared — squad does not do this, which is good, and must keep provider instances immutable.
