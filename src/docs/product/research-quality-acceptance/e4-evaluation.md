# E4 中断与恢复离线结果

基线 879de1d 加起点未提交快照与当前代码分别执行相同三个 native 运行器测试：未知外呼不重发、结算失败后保存响应且恢复不重发、已检查点分项在中断后保留且撤权过滤；两侧均 3/3 通过。该能力在起点快照已有，不可归因于本轮新增。当前侧另运行混合事实检查点重放与精确引用范围测试，1/1 通过；起点快照不存在此测试，非成对结果。故障前后按可复核分项统计的完整保留率未计算，不能从测试数量替代。

当前侧独立 PostgreSQL 的 native API 恢复和跨进程并发准入另外 3/3 通过，细节见 protocol。此组实际使用 PostgreSQL 存储，未杀进程后重开，因此不能证明分项和计算跨进程重开或导出一致；旧式 PostgreSQL 重开夹具不兼容当前契约。中断矩阵中的持久重开、并发编辑、完整授权及导出仍须针对新接口补测。

## 原生检查点跨进程重开补测

在独立 PostgreSQL 16 Alpine 容器（128 MiB、随机凭据和本地随机端口）加载 `001_research_state.sql` 与 `002_operation_state.sql`，运行 `test_research_quality_postgres_reopen.py`：**1 passed**。首个 Python 进程经真实研究 API 依次读取资料、保存两期收入事实、计算 20% 增长、检查点记录问题分项，在下一模型调用处取消并重复相同取消请求，然后退出。第二个 Python 进程重新导入应用并打开同一数据库，核对同一版本的两条事实及其唯一 ID、唯一计算及输入、已保存的收入分项和未回答的 EPS 分项；授权导出与版本内容一致，另一账号读取及导出均为 404。原创建请求以相同幂等键重放返回原操作，旧父版本写入返回 409，版本数保持不变；第二进程的替身 provider 会在外呼时直接报错。容器及临时数据随后删除。

该测试验证一次取消后持久重开，未覆盖进程在版本事务中途被强制终止、未知外呼对账、撤权后重开或所有故障点的保留率，不能推断完整中断矩阵已经通过。

## 提交检查点后强杀与恢复

在新建隔离 PostgreSQL 16 Alpine（128 MiB）加载两项迁移后，运行 `test_sigkill_after_submission_checkpoint_recovers_without_external_call`：**1 passed**。首进程通过原生运行器读取资料、提交带引文答案；在最终版本写入入口暂停，由测试父进程发送 SIGKILL。第二进程重新连接 PostgreSQL，确认提交检查点已持久化且只有原父版本，令原操作租约过期后恢复交付：恰好产生一个子版本，正文及导出版本一致，记录的两次模型调用未增加。同一恢复幂等键返回原恢复操作；不同新键返回 409，版本数不变。隔离容器随后删除。相邻的原生恢复和累计预算/未知外呼阻断测试另 **2 passed**。

首次故障注入的第二进程使用了不同 provider 标识和策略，恢复按配置变更返回 `changed`，该次不评价恢复；对齐配置后发现同键重放被版本检查提前拒绝，现已调整为先按账户、主题、原操作和原请求哈希查找已接受的操作，新键仍执行版本检查。测试夹具的一次语法错误和一次数据库初始化就绪竞争均在到达故障断言前终止；修正后上述结果为最终实测。
