# ForesightNine 通用金融问答与研究交付改进方案

2026-11-23 · 实施提案 · 代码基线 `aaab3d7`

用户可以直接问任何金融问题，也可以在研究中改变要求。系统对每一次交付负责回答三件事：用户要知道什么或决定什么，现有证据支持回答到什么程度，还有什么实际可做的工作。接得住任何问法，与拥有所有市场的数据，是两项不同的能力。数据不足时，仍应尽力给出有依据、对决策有用的回答。

## 一　当前缺陷和改动范围

线上 Apple 主题的原问题是“分析一下 Apple 的市值变化”。系统找到了价格和年度加权平均股数，把关于股价的结论标记为核心问题已答。检查两个时点的市值变化，只需可比的两端市值，或两端各自同口径的价格与发行在外股数。只有用户索要逐日曲线时，才需验证整段序列。

在本次规划前对发布版本的完成判定函数做过离线反例检查。同一条股价证据对“市值变化”和“市值走势如何”得到相反结果。稳定币交易价格被接受为赎回权的依据，政策公布日期被接受为生效日期，合同原文明确禁止的事项也被判为已答。这些复现说明判定函数会放行错误提交。它们不衡量整套 Agent 在自然提问下的错误率。

保留已经工作的后台执行、追加指令、停止、检查点、操作去重、证据位置、确定性金融计算和已保存成果展示。替换从词语重合、指标命中或模型的“已完成”推导问题已答的路径。原有方法包继续指导找资料和检查口径；选不中方法包的题目也走完整流程。既有连续执行与指令协议见[研究运行方案](research-run-instructions-plan-2026-11-23.md)。

## 二　从用户原话确定要交付什么

每轮先保存原问题和用户明确给出的条件，再生成少量会影响答案的“待回答问题”。每项记录原文依据、重要性、期望交付、适用条件以及怎样才能回答。简单概念题可以只有一项，复合问题可以同时包含事实、解释、计算和决策。用户明说的要求与 Agent 自选的研究范围分别记录。例如，用户没有指定期间，Agent 可以选有代表性的区间并披露，不能把“五年逐日全量数据”变成用户的硬要求。

遇到可能改变结论的歧义，优先用已有资料消解。可并列回答的歧义直接给两种解释，有合理默认值的先说明假设并推进。仅在几个解释会导向明显不同的决定，且没有有用的条件答案时，才向用户问一个关键问题。专业名词、语言混用、只有一句口语提问都不能成为启动障碍。

| 用户可能问 | 应交付的内容 | 足以改变答案的区别 |
| --- | --- | --- |
| “实际工资这几年到底涨了吗？” | 指定地区、期间的可比购买力变化；必要时展示名义工资和价格指数的计算 | 就业人数、名义工资、实际工资各自回答不同的问题 |
| “这个稳定币脱锚了，我能按面值赎回吗？” | 分开回答二级市场价格和用户能使用的赎回渠道，核对发行方适用条款、资格、费用、时点 | 链上成交与发行方兑付义务；直接赎回与通过交易平台卖出 |
| “明年交学费的钱，适合放这只债基吗？” | 把付款日期、可承受缺口、赎回到账时间和损失情景放在一起比较，给出条件判断及替代选择 | 历史收益、可赎回、能按时足额到账是三件事 |
| “这个政策从何时影响现有贷款？” | 从适用版本中查生效日、过渡条款和适用人群，说明哪些贷款会受影响 | 公布日、生效日和合同重定价日可能不同 |
| “油价上涨导致这家航司利润下降了吗？” | 核对时序、燃油敞口、套保、价格传导和替代解释，按证据强弱措辞 | 同期变化支持相关性；因果和贡献比例需要额外依据 |
| “久期是什么？能用一个例子说明吗？” | 直接解释概念与适用条件，用标明假设的数字演算 | 例子使用模拟输入即可，无须启动实时行情研究 |
| “如果利率再涨，我的房贷和组合会怎样？” | 在指定或披露的利率情景下，分别说明现金流和资产变化，列出关键敏感项 | 用户余额、合同条款、假设和预测分别记录 |

这些是验收样例。执行器按每个子问题实际需要的证明方式工作。股票、债券、基金、外汇、商品、衍生品、数字资产、宏观政策和家庭财务都可组合使用同一流程。

## 三　逐条判断依据能支持什么

**拟新增的交付记录**有四组。沿用主题、版本和证据 ID，名称供工程实施使用。

| 记录 | 必要字段 | 用途 |
| --- | --- | --- |
| 问题要求 | 稳定 ID、原文位置、期望交付、核心或可选、适用对象与时点、用户条件或已披露假设、版本 | 判断答案是否偏题，追加指令后确定受影响项 |
| 候选结论 | 一句可核验的表述、关联要求、结论性质、来源位置或计算 ID、假设、用户提供的信息 | 分开保存披露事实、计算、解释、情景和建议 |
| 证据核验 | 结论和要求 ID、证据版本、定位与口径结果、语义关系、反例或冲突、理由、未验证项 | 回答“这段证据如何支持这句话，这句话又如何回答原问题” |
| 缺口和行动 | 对应要求、缺失内容、可执行工具及权限、期望获得的证据、已试路径与结果、什么新信息值得再试 | 决定继续工作、给条件答案、询问用户或交付 |

**核验分两步。** 程序检查来源权限、版本、原文位置、币种、单位、日期、计算输入及公式。样本区间、调整口径、基准或实体无法对齐时，保留冲突。随后做语义核验，对照原问题、候选结论、短段原文及必要上下文，分别判断直接支持、仅支持较弱结论、矛盾、无关或证据不足。遇到否定、例外、时态、比较或因果，核验结果需要指出影响判定的原文或缺失前提。

简单计算已由可复核的公式和匹配输入完整覆盖时，可以直接交付。需要解释或建议时，可用现有已配置模型对同一批核心结论做独立于写作步骤的复核。复核输入不带撰写者的自评结论，每项输出须绑定有效证据 ID 和对应原文。复核模型也可能出错，其判断不得覆盖确定性冲突、补造事实或扩大权限。格式损坏、复核不可用、意见分歧时，保留可验证部分并降低结论强度。按要求版本和证据版本复用有效判定，避免每个句子再调用一次模型。模型、协议及支持的参数沿用连接配置。

对每个核心要求，分别记录“有依据的回答”“在明确条件下成立”“证据冲突”“仍缺资料”。只有含有实质答案的前两类可以计入已回答；条件必须出现在用户可见正文里。来源数量、词语重合、模型信心和工具调用次数都不能单独推进状态。结构化方法缺失时走通用语义核验；无法验证就保留未知。一个报告允许同时给出确定事实、合理推断和仍有争议的解释。

## 四　按问题选择信息和工具

保留一个协调 Agent。为现有及后续连接器描述可提供的数据、适用范围、时效、权限、费用条件和常见失败。计划器根据“缺什么证据”选择工具。先复用用户材料、已有来源及可复核计算，再选择必要的发现、获取或核验动作。外部文本始终作为资料处理。

- 数值和序列需说明对象、时点、单位及口径。优先找直接值，也允许有来源的推导。手续费、拆分、汇率、份额或合约乘数只有在会改变答案时才纳入。
- 文档与制度问题定位有约束力的文本，连同例外、修订和适用对象读取。二手报道可以发现线索。无法取得有效版本时明确剩余不确定性。
- 数字资产任务按所需能力组合发行方文件、交易场所行情、链上记录或协议数据。记录网络、合约、计价币、区块或时间点。链上可观察行为与链下权利分别核验。连接器缺失时先用获准的一手文件或用户资料。
- 归因、预测、模拟分开交付。归因检查机制和相反证据；预测列出条件、期限和失效条件；模拟保存假设、公式与结果。无法估计概率时可以只给情景。
- 搜索无结果、原文被拒、供应商暂时故障、许可禁止、技术上没有工具分别记录。一次反证搜索不能耗尽核心问题的检索路径。一篇文章被拒时，按相关性和权限选择其他原始来源。来源确有变化、新获授权或暂时故障已恢复时，可以再试。

第一期交付核验流程及现有能力目录。新增数据供应商按独立任务评估覆盖、授权、时效和成本。计划中的连接器不能出现在已可用能力中。

## 五　个人投资和家庭财务问题

从用户的这句话提取明确条件，例如“一年后付学费”“这笔不能亏”“我有美元支出”。资产负债、收入稳定性、应急储备、税务地区和风险承受能力，只在会改变本次判断时才需要。每项输入标明用户提供、账户内经授权复用、暂用假设或未知。仅使用本账户当前获准的资料，发送给外部模型的内容限于解决任务所需；搜索公开产品信息时去除用户身份和私人金额。长期复用个人资料需用户选择，临时假设不得写成已确认偏好。

延续学费示例，系统可先比较到期可用金额、赎回时间和不利情景。如果“能否承受临时或到期亏损”会改变选择，先列出能承受和不能承受两种情况下的判断，并解释哪一项信息最关键。产品条款、费率或赎回规则属于公开可查事项，交给 Agent 查询。只有用户才能提供的关键事实，可以在原研究里询问，回答后接续原进度。

输出包括判断、对该用户成立的理由、替代选项、主要代价和会改变选择的条件。金额或比例须绑定用户目标、假设与可复核的计算。涉及具体税务、合同或地区适用性时标明依据版本和适用范围。产品继续提供研究与模拟，交易执行与托管在首版范围之外。

## 六　自动继续与交付规则

| 实际状态 | Agent 的动作 | 用户看到什么 |
| --- | --- | --- |
| 核心问题未答，存在获准且有希望的新路径 | 缓存已通过的结论，执行下一步，依据新证据重验受影响项 | 研究中；进度用具体语言说明正在核对什么 |
| 可验证的回答只覆盖一种情况 | 尝试补足会改变答案的条件；其余条件可明确列出时交付分情况的答案 | 正文给出条件和结论 |
| 公开材料查不到，私人条件会决定答案 | 先完成独立工作；仅在确需输入时保存检查点并等待 | 一条具体问题，说明答案将改变哪项判断，可补充或接受现有分析 |
| 可用路径已用尽，或用户明确预算耗尽 | 保存已核实内容、无法回答的部分、尝试记录 | 有可读成果显示“已完成”，正文明确剩余未知；展开可见依据 |
| 服务故障且可恢复 | 后台退避、重连、从检查点恢复；外呼结果未知时先核对回执 | 正在恢复；无须重复提交 |
| 故障后最终没有可读成果，或用户主动停止 | 保存故障或停止原因和已取得的资料 | 分别显示“执行失败”或“已停止” |

同一路径按“要解决的问题、工具、有效参数、资料版本、权限和失败类型”去重。连续改写同义检索词且没有新增证据，不构成有效进展。新来源、新口径、替代计算或不同假设可以构成新路径。候选行动要说明可能填补哪个缺口。没有可行路径时允许收尾，用户无需替 Agent 反复点击继续。沿用单次请求超时、取消、外呼幂等和费用记账。运行预算遵守用户显式设置，未设置时不加总调用数、费用或时长上限，显式零照做。

## 七　运行中追加要求和前端

复用稳定的 turn ID 和指令序号。用户发送补充后立即得到已保存回执；协调器在下一次安全边界读取新指令，更新要求版本。例如从“分析稳定币”细化到“我只关心普通持有人能否赎回”，共用的发行方文件可以复用，已过时的价格分析退出核心交付。相互冲突的指令保留顺序、适用范围与替代关系。后台提交成果前同时核对最新指令序号和证据版本，避免刚收到的要求被旧结果覆盖。未知外呼结果保留待核对状态，进程恢复不重复扣费。

列表与详情复用同一运行生命周期。正文优先回答问题，在会改变用户理解的位置说明条件或缺口。数据日期、细节、退避记录、被删的候选结论放在可展开的研究记录。普通交付保留追问入口；确需用户提供资料时展示与缺口对应的操作。研究记录能从结论跳到原文、从计算跳到输入，也能看到某条新要求最终如何处理。用户确认过的核心判断出现变化时生成版本差异，保留接受记录。

## 八　工程实施顺序和阶段出口

| 阶段 | 主要改动 | 可检查的阶段出口 |
| --- | --- | --- |
| 1 基线与题集 | 记录当前版本、运行快照、错误路径与预算；冻结独立题及评分规则 | 同时复现错交、过度拒答和可正确交付的对照，用同一输入比较新旧判定 |
| 2 核心判定 | 在 `research_topics.py` 定义问题要求、核验和行动记录，生成契约；在 `research_delivery.py` 统一合并规则；将 `research_evidence_requirements.py` 中的专门核验作为证据输入，移除通用词语重合放行 | 同一证据对不同问题得到不同结果；可复核的计算、直接披露和条件答案仍能通过 |
| 3 运行闭环 | 接入 `research_tool_executor.py` 的提交、`research_runtime.py` 的最终组装、恢复和持久化；进度、报告和导出使用同一份判定 | 原问题、追加指令、修正引文、外呼失败、服务重启和预算耗尽均走同一闭环；旧草稿不能绕过最终核验 |
| 4 个人问题与能力选择 | 接入用户条件、条件答案、隐私处理、工具能力声明、原轮追问；保留资料和用户判断的版本 | 个人决策题能给出条件性判断，在缺关键私人事实时只问有价值的问题；无行情或无链上连接器时仍能交付获准的文档分析 |
| 5 用户体验与发布验收 | 统一主题列表、详情、进度与研究记录；检查桌面和手机；固定题集做全链路盲测与成本对照 | 页面能解释“结论是什么、依据是什么、是否需要我做事”；发布证据列明通过项、失败类型、未验证能力和回滚目标 |

开发期直接替换内部实现，历史答案保留其生成时的版本和原有表述。离线重放用于对照，不自动改写既有研究，也不因升级自动产生模型费用。开发测试与真实模型对照、线上发布分别按各自授权执行。

## 九　如何证明改进有泛化能力

1. **按推理错误设计题目。** 同时覆盖事实与定义、数值比较、权利与条款、归因、个人选择、预算与现金流、未来情景、冲突材料、资料不可得。交叉覆盖不同市场、资产、语言和数据质量。Apple 和本次讨论过的反例全部留在公开开发集，不计入独立验证成绩。
2. **成对改变一个因素。** 同题换问法应得到一致结论；同一证据配不同问题应产生不同判定；只改否定、有效期、链、计价单位或用户资金期限，结论应在需要时翻转；删掉关键资料应降低结论强度，补回资料应能解除缺口。每组都包括本来就应该直接回答的正例，防止靠“全都证据不足”提高表面成绩。
3. **分层验证。** 第一层使用冻结记录回放确定性检查和提交判定，不调用模型。第二层固定材料与工具回执，单独比较有无语义复核及其额外成本。第三层按自然提问跑完整 Agent，不向它泄露预期答案和工具路径。最后在已授权预算下做少量真实来源验收，分别记录供应商波动和方法错误。浏览器只测完整用户流程。
4. **预先写下指标和门槛。** 建议初始约 30 个独立基础任务，再配成对变体；按基础任务组拆分，禁止把同题改写散入开发集与保留集。记录核心要求误判已答率、充分证据被拒率、已知可行补救路径执行率、不必要追问率、无新增证据的重复外呼数、单位有效交付费用和延迟。按题型报告分子与分母；样本不足时不宣称整体准确率。建议在冻结的严重反例中，把“相反条款获通过”“代理指标当目标值”“忽略明确资金期限却给无条件建议”“越权或重复付费外呼”作为零容忍的候选发布门槛。其他数值门槛在基线测量后、查看候选结果前登记。
5. **隔离评估偏差。** 题组、数据快照、金标准和评分说明版本化，开发者不使用保留集反复调提示词。语义真值无法独立判定的题标为未裁定，单列报告，不算通过。一次实验只改一个主要因素，固定协议与模型配置、工具许可和预算，记录实际调用和不确定性。一个模型写答案再给自己打分不足以充当独立质量证据。

交付顺序先解决“会不会把没有回答的问题判为已答”，再解决“该继续找什么、该何时问用户”，最后验收真实研究质量。每个阶段以可复现的用户结果收尾。
