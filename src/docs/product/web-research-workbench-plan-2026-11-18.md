## 2. 研究入口：以主题为单位的多轮工作台

本文定义研究入口。跨公司机会比较、画像驱动的仓位建议及收益复盘的整体方向见[产品定位](fusion-finance-ai-macro-plan-2026-11-11.md)。

用户在一个研究主题里连续提问。每一轮都是一次独立运行，拥有自己的预算、恢复、结算和运行记录，并在完成后生成一个新的研究版本。新版本累积此前已经核验的资料、事实和计算，以及仍然有效的结论。

多轮的上下文来源是**结构化研究状态**，不是模型对话记录。这与项目原则“核心研究状态独立于聊天上下文保存”一致，也能控制上下文长度，并让每一轮都可以复核。

| 概念 | 含义 |
| --- | --- |
| 研究主题 | 持续存在的研究单位，固定研究截止时间 `as_of`。修改截止时间需要新建主题。 |
| 轮次 | 一个用户问题加上一次运行，以及这次运行的回答、新增结论、缺口、停止原因、用量和过程事件。 |
| 研究状态 | 跨轮累积的资料、事实、计算和结论，以及当前未解决的缺口。 |
| 版本 | 每轮完成或用户复核后保存的不可变快照，包含研究状态和全部轮次记录。 |
| 继续运行 | 同一轮次从检查点恢复，问题不变。它与开始新的一轮是两个不同操作。 |

### 2.1 一轮研究可以做什么

- **追问**：提出新问题，例如“再比较一下营业利润率”。模型可以直接引用以前记录的事实 ID 进行计算，不必重新读取原文。
- **补充缺口**：针对上一轮的缺口继续取证。界面提供快捷入口，内容是预填的问题，后端仍按普通的一轮处理。
- **寻找反方**：要求针对指定结论寻找反证。
- **深挖引文**：指定一条已保存的引文，对应现有的 `focus_citation`。
- **添加资料后再问**：新资料挂到主题后，下一轮自动纳入资料清单。
- **解释型追问**：例如“这个 17.79% 怎么算的”。模型可以不调用工具直接提交回答。这样的回答不产生新的证据，界面会标明回答只基于已有记录。

### 2.2 多轮的规则

1. **已有成果只增不删。** 新一轮不能删除或改写以前的结论。新证据与旧结论冲突时，新结论标为“与已有结论冲突，待复核”，并关联被挑战的结论 ID。
2. **用户确认的判断受保护。** 用户已经确认的结论，只能经由用户复核接受变更，接受时记录差异与依据。这一步属于阶段 C 的版本差异基础，首版先实现冲突标记和人工处理。
3. **同一主题同一时间只运行一轮。** 后端已经有这项限制。运行期间前端锁定复核编辑，后端的版本冲突检查继续作为兜底。
4. **预算按轮计算。** 每轮单独设置预算，留空表示不设上限。界面同时显示本轮用量和主题累计用量。
5. **问题原文保存在轮次记录中。** 回看、导出和恢复都能看到每一轮实际提出的问题。

## 3. 页面结构

```
登录
└─ 研究列表 /research
   ├─ 新研究 /research/new
   │    一个问题即可开始；可选资料、范围、截止时间；高级设置放预算和来源开关
   └─ 研究主题 /research/:topicId
        ├─ 顶部：主题问题、版本选择、复核状态、截止时间
        ├─ 主区：轮次对话流
        │    每轮：问题 → 运行状态（运行中显示实时过程）→ 回答卡片
        │    回答卡片：报告、本轮结论和引文、数字和计算、缺口、停止原因、用量，过程可展开
        │    部分交付卡片：已取得的成果、缺口、停止原因、下一步按钮
        ├─ 底部输入区：追问输入框、添加资料、快捷操作（补充缺口、找反方、深挖引文）、本轮高级设置
        └─ 侧栏：研究状态
             结论汇总：跨轮的支持和反方结论、冲突和待复核标记
             证据：资料、已读片段、未核验候选链接、权限和时间
             数字：事实表、计算，支持重算和手动计算
             复核：确认或保留意见、备注、编辑结论、版本对比、导出
资料阅读器（弹出层）：原文、引文高亮、上下文、原始 PDF
设置：模型配置、行情配置、账户
```

界面原则：

- 部分交付是正常结果，不应作为错误页显示。
- 原文片段、已记录事实、确定性计算和模型解释使用不同样式。候选链接只是线索，不能被引用。
- 引文可以定位并高亮原文。界面说明服务端只核对引文位置和数值，没有核对语义。
- 模型输出和资料原文都视为不可信文本，只按纯文本或安全 Markdown 渲染，不渲染 HTML。
- 高级设置只放后端实际生效的选项。

## 4. 后端先行改造

| 编号 | 改造 | 当前问题 | 完成标准 |

| B4 | 多轮研究 | 每次运行都从空状态开始，提交时整体替换版本内容，追问原文只保存哈希。 | 见 4.1。 |
| B5 | 账户资料列表 | 只能按版本查询资料。 | 可延后。实现后支持跨主题复用资料。 |
| B6 | 报告格式 | 报告是纯文本还是 Markdown 没有约定。 | 在契约中写明，建议使用受限 Markdown。 |

### 4.1 B4 多轮研究设计

**数据结构**（开发期直接调整 schema，不做旧数据兼容）：

- `ResearchContent` 新增 `turns`。每轮记录 `turn_id`、`question`、`question_origin`、`operation_id`、`parent_version_id`、`status`、`reason`、`report`、本轮新增的结论 ID、本轮缺口、用量和 `events`。
- 结论、事实和计算分别带稳定 ID 和来源 `turn_id`。结论新增 `challenges_claim_ids` 和复核状态。
- `summary` 改为用户维护的研究总结，Agent 不覆盖。每轮回答保存在对应 `turn.report` 中。
- `content.run` 改为 `turns[-1]`，不再作为单独的单次运行记录。
- `limitations` 表示当前未解决的缺口，每轮自己的缺口保存在轮次记录中。

**运行输入**：新一轮的初始状态包含有长度上限的研究状态摘要：

- 资料清单与已读范围；
- 已记录的事实，包含 ID、数值、单位、期间和引文位置；
- 已有计算；
- 已有结论，包含 ID、角色、引文和复核状态；
- 未解决的缺口；
- 用户复核意见。

这些内容明确标为“既有研究记录，非新核验证据”。`calculate_financials` 可以直接引用既有事实 ID。模型需要重新核对原文时，使用 `read_sources` 读取。摘要超过上限时按相关性和时间截断，并告诉模型被截断的部分。

**提交合并**：

- 资料、事实和计算按 ID 累积并去重。
- 新结论追加，旧结论保留。冲突结论标为待复核，用户已确认的结论不会被改写。
- 新版本的父版本是本轮开始时的版本。运行期间如果用户保存了编辑，保持现有 409 冲突行为；前端在运行期间锁定编辑。

**恢复**：

- 继续运行绑定原轮次，问题、资料和配置都要一致，沿用现有校验。
- 新一轮使用新的幂等键和新的 `turn_id`。

**测试**：

- 离线两轮端到端测试：第一轮记录两期收入，第二轮直接用第一轮的事实 ID 计算增长率；新版本同时保留两轮的结论、事实和计算。
- 第二轮提交冲突结论时，第一轮已确认的结论保持不变，并出现冲突标记。
- 第二轮中途失败后可以继续运行，第一轮的成果不受影响。
- 导出包含全部轮次和问题原文。

## 5. 前端技术方案

- **框架与构建**：React 18、Vite 和严格模式 TypeScript。
- **路由**：使用路由库。OAuth 回调路径与后端 `return_uri` 允许列表保持一致。
- **数据请求**：使用 TanStack Query 处理轮询、缓存和 `Retry-After` 退避，运行事件通过 SSE 订阅。
- **类型**：从 `@foresightnine/contracts` 生成的类型导入，不在前端手写接口类型。
- **API 客户端**：同源请求，带 Bearer token。写操作使用幂等键，并在本地保存待确认的运行请求，刷新后重试同一请求时不会重复发起运行。
- **样式**：使用 `@foresightnine/design-system` 的设计令牌和独立 CSS 文件，符合部署 CSP。
- **语言**：中英文文案集中管理。
- **测试**：
  - 组件和客户端测试使用 Vitest；
  - 端到端测试使用 mock API，fixture 来自后端测试中的真实响应形状；
  - 每个里程碑结束时在真实环境运行一次受控验收，并记录结果。

| 阶段 | 内容 | 完成标准 |

| 后端 1 | B1 结论角色、B3 契约清理并生成类型 | API 测试通过，契约与实现一致。 |

| 前端 M1 | 新研究、第一轮运行、轮询和取消、回答卡片、资料阅读器、恢复与继续 | 只输入问题就能完成第一轮。部分交付能看清已有成果和缺口。离线和真实环境各通过一次。 |
| 前端 M2 | 多轮对话流、底部追问区、快捷操作、研究状态侧栏、实时过程 | 同一主题完成两轮研究，第二轮复用第一轮的事实，冲突标记可见。 |

| 以后 | 阶段 C 的变化收件箱和观察条件；FM 与观点组合研究入口 | 等后端和产品定位确定后再规划。 |

后端 1 与前端 M0 可以并行。M1 的回答卡片依赖 B1；M2 依赖 B2 和 B4。

## 7. 待定事项

- **研究状态摘要的上限和截断策略**：需要用真实任务测量 token 占用，并固定参数后再验收。
- **冲突结论的接受流程**：首版只做标记和人工编辑。与旧判断差异的展示和接受记录，在阶段 C 设计时细化。
- **主题累计费用**：后端结算目前不能确认实际费用，`cost_status` 为 `unknown`。界面只显示后端记账的数量，不换算为金额。
