# ForesightNine 个人投资决策 Agent 后端功能宏观规划

2026 年 11 月 27 日 · 供产品、后端和研究评估共同使用。产品目标来自[定位与核心体验](fusion-finance-ai-macro-plan-2026-11-11.md)。本文提出功能分工、数据关系和交付顺序，作为后续专项规格的依据。现状以仓库提交 `b7acb77` 为参照，工作区正在开发的垂类按相应任务书衔接。

## 1. 后端要交付哪三种判断

用户可以直接问一个公司问题，也可以持续维护一组持仓和候选。后端应能回答“这家公司发生了什么”“以这个价格，它在备选机会里有多大吸引力”“对我的这笔资金，现在有哪些合理选择”。三种答案有各自的依据，可以同时呈现不同方向的判断。例如，公司经营改善，估值可能已经反映增长；标的吸引力上升，用户的同类持仓也可能已经过于集中。

| 决策层 | 输入 | 用户能核查的交付物 |
| --- | --- | --- |
| 公司或产品研究 | 问题、标的身份、截至日、获准使用的原文和金融数据 | 事实与计算、解释、支持和反对证据、缺口、哪些变化会推翻判断 |
| 机会与相对推荐度 | 一组持仓和候选、参考价格、统一期限、币种、情景及替代机会 | 推荐理由及其适用条件、预期回报区间、下行风险、排序对假设的敏感性、无法比较项 |
| 个人组合选择 | 以上结果、用户确认的资金目标与画像、持仓、现金及约束 | 建仓、补仓、持有、减仓或保留现金的备选方案，当前和建议权重、资金来源、调整理由、受影响的风险及复核条件 |

只有研究需求时直接完成第一层。需要讨论仓位时再请求影响该决定的最少个人信息。首个可试用版本仍以研究、模拟和一次有依据的更新为交付边界。面向真实用户开放个性化建议，要另行验证数据、方法、许可及服务地区条件。真实下单与资金托管在首版范围之外。

## 3. 七个业务模块及其边界

建议沿用 FastAPI、PostgreSQL、现有运行器和事件调度器，以代码模块和版本化业务对象划分职责。下列划分不要求拆分服务。

| 模块 | 后端责任与关键设计 |
| --- | --- |
| **资产、行情与信源** | 分别标识发行人、证券、上市地、币种和交易日历；基金等产品单独标识，并在有许可和有效日期时关联底层持仓。行情保存价格类型、复权口径和时点。新闻识别原始发布方、转载、修正及其影响对象。原文、提取事实、计算、模型解释分别存放。|
| **公司研究与判断** | 将财报、电话会、公告和竞争对手证据组织为可版本化的判断。每条判断绑定关键假设、原文区间、数值口径、反证和触发复核的条件。允许证据只支持公司经营变化，股价归因或持续性仍待核实。|
| **机会发现与比较** | 从获准覆盖的关注名单、持仓、同业及用户允许的候选范围发现机会，记录入选原因与未检查范围。同业先比较合适的经营指标；跨行业在同一估值日、期限、币种及基准下比较情景总回报、下行和估值依赖。推荐度输出相对结论和可能令次序反转的条件。未经校准的判断不映射成胜率；没有可比基准时保留分项分析。|
| **投资画像与组合账本** | 每个用户可有多个资金目标。画像记录期限、用途、现金需求、风险承受意愿与实际损失承受能力、用户确认的集中度及禁限项，保留来源、生效时间和版本。持仓支持先录权重，后补数量、现金、交易、费用、分红、公司行为和汇率。自选、模拟与实际记录分开。账户范围或现金未知时标明覆盖缺口。|
| **个人方案与模拟** | 基于同一版机会、画像和组合生成可比方案，包括维持现状。确定性代码计算权重、资金平衡、直接和间接暴露、集中度、流动性和费用。说明新增现金或卖出哪项持仓提供资金。资产范围不全、穿透数据陈旧或约束不可满足时，给出条件方案及待补资料。仓位区间算法、风险模型和 FM 在产品中的最终角色留待专项对照。|
| **变化跟踪与复核** | 监听价格、新闻、披露、组合和画像变更。沿“事件—证据—判断—机会—账户方案”定位受影响对象，只重算相关结果。价格波动先更新估值，基本面证据变化才重新审查经营判断；资金目标变化可只重算个人方案。同一事件多次到达合并，修订或撤回保留版本；收件箱分别返回静默、检查失败与发现重要变化。|
| **决定记录与收益复盘** | 在建议形成时封存价格、期限、估值与执行假设、基准、情景回报及所用版本。单独记录用户采纳、修改、拒绝或暂缓；只有真实成交记录才更新实际交易账。到期对照标的总回报、建议模拟组合回报与用户实际回报。分析预期差异来自经营假设、市场估值、仓位、汇率、费用还是执行时点，证据不足的残差单列。|

### 收益服务需要的最小数据

事前情景按期限给出可能的收益和下行；只有分支及概率有明确依据时才计算概率加权预期。标的实际总回报统一处理分红和公司行为。模拟组合固定生效时间、可成交价格、调整规则与费用，按当时可知数据沿时间推进。实际账户收益根据可对账的期初期末资产和期间流水计算，外部出入金与买卖、分红分开。具备分段估值时可用时间加权口径解释策略表现，具备带日期的资金流和期末估值时可用资金加权口径解释用户体验，并披露口径与覆盖期间。缺成交或现金记录的账户仍可查看标的表现或模拟结果，实际回报标为资料不足。

## 4. Agent 编排与持久状态

一个面向用户的协调者持有本次问题、授权、可用数据和停止条件。它选择必要的研究流程，读取各模块的版本化结果，并对最终回答负责。角色是逻辑职责；是否并发、是否使用独立模型，按任务质量、可靠性及实际成本决定。

| 入口或触发 | 调度策略 | 交付或停止条件 |
| --- | --- | --- |
| “公司上季毛利率多少？” | 走通用运行时和确定性取数，必要时核对披露 | 返回期间、口径、数值与出处后结束 |
| “A 和 B 哪个更值得跟踪？” | 复用有效公司底稿；有决策影响的缺口才启动财报或行业工具，比较层统一期限、参考价格与情景 | 给出有条件的推荐次序、最强反证和未知项；比较无依据时说明缺哪一侧 |
| “下一笔资金补 A，还是建仓 B？” | 读取用户确认的画像与组合，把维持现状纳入备选。模型解释机会和权衡，确定性代码检验资金与约束，保存方案版本 | 返回可行方案及差异；若关键输入缺失，给出仍能成立的比较并提出具体补问 |
| 新公告、价格触发或用户更改目标 | 调度器识别受影响对象；协调者复用未变的证据，对到期假设做增量研究，将差异送入收件箱 | 返回变化原因、受影响判断及能否维持原方案。修改已确认判断须记录用户决定 |

业务对象以“**研究主题与证据版本 → 公司判断 → 机会比较快照 → 组合方案 → 用户决定 → 到期复盘**”相连。每个组合方案同时引用画像版本、持仓版本和数据截止时间；实际交易有独立来源。新行情或用户编辑生成后继版本，历史复盘可回答“当时知道什么”。公司事实可在许可和数据可见范围内复用；用户上传资料及其派生结论、持仓、画像和实际收益按账户隔离。所有版本、导出和删除操作沿用相应账户权限。

### 接口与运行保障

- **读取和提交。** 延续现有主题、同业、雷达和收件箱资源。后续按业务能力补画像、组合、机会比较、模拟方案、决定和复盘接口。读取已保存结果与显式刷新分开；长任务复用异步操作、进度流和检查点。客户端可取得状态、截至日、输入版本、证据、计算和缺口。具体 URL 和 schema 在分项设计时确定。
- **运行与恢复。** 用户未设运行预算时保留未设置，显式零、空来源和关闭发现逐路径执行。模型、搜索、数据及子流程共用本次授权与预算，外呼前检查、返回后记账；显式费用上限无法核价时保留已有成果。取消、重试、租约接管与幂等键复用既有机制，外部调用或费用未知时先对账。后台订阅按自己的授权范围运行。
- **时点与质量。** 分记事件发生、公开、获取、修订和决策时间。标示最新交易日、覆盖与延迟，历史研究只读当时可得版本。模拟数据与真实证据隔离；FRED 授权边界沿用项目规则。数据、模型和搜索协议独立配置。服务端决定工具权限，外部材料无法改变授权。

## 5. 交付顺序与验收出口

以下顺序把新目标接到既有 B、C、D 阶段，作为实施建议。在建行业工具可继续独立推进；完整覆盖所有市场和行业不构成首条链路的前置条件。

| 建议增量 | 依赖与交付 | 可观察的验收出口 |
| --- | --- | --- |
| **研究与更新（B、C）** | 打通已有公司底稿、通用追问、同业比较及事件台账，统一传递证据、版本和缺口 | 两个标的在同一时点完成一次可核验比较；加入新披露后能指出哪项假设变化。同一新闻转载两次只形成一项复核；未受影响的判断仍可回查。构成首个研究试用闭环。 |
| **组合上下文与机会（衔接 D）** | 接入阶段 D 手动持仓与 V5 关系敞口，在此之上增加分目标画像、候选集合、同业与跨行业机会比较 | 同一公司事实在两个账户保持一致，而不同目标或集中度可改变机会优先级。缺现金、缺权重、行情过期和重复暴露均如实表达。 |
| **条件方案与模拟决定** | 依赖定版的机会比较、画像与组合。先交付可复算方案、用户决定和事前快照，按地区及验收条件单独决定真实个性化服务开放范围 | 同一输入可复算资金来源、前后权重与现金需求；覆盖补仓、减仓、保持与无可行方案。用户确认建议不会产生实际成交。 |
| **实绩与前向复盘** | 先接受最少必要的手动或经授权导入的交易与现金流；核对数据后执行定期、到期及条件触发复盘 | 用含分红、入金、费用和一次调仓的样例独立对账，分别展示预期、标的、模拟及实际收益。晚到修订可纠正当前记录，同时能回到当时建议。 |
| **扩展运营（E）** | 根据试用中的更新价值、数据许可和成本决定更多市场、投资产品、提醒渠道与付费方案 | 按市场、任务及来源报告覆盖和失败，分别计量首次研究、增量更新和持续观察的成本；预登记前向样本评估投资效果。 |

### 一条贯穿全程的验收样例

测试账户直接持有甲公司，占净值 20%，并持有一只占净值 15% 的 ETF。若同一时点可核验的基金持仓显示甲占该 ETF 的 10%，对甲的已知直接加穿透暴露为 **21.5%**。基金剩余部分仍归在相应资产，不重复计入净值；穿透成分缺失时只报告已知暴露和未知范围。另选一个不同行业的乙作为新增资金候选。以上数值均为验收夹具。

先比较甲、乙与保留现金，再让一个测试画像增加近期现金需求，检查只有个人方案改变。随后送入甲的新披露及其转载，检查触发一次复核并保留原建议。最后让用户模拟接受方案但录入不同的实际成交，核对建议模拟和实际收益各自沿正确的流水计算。这条链路同时检验专业工具能否交接、用户是否保有决定权，以及事后能否解释收益差异。

研究验收关注事实与计算、引文的语义支持、有效答案与错误弃答、提醒误报漏报、核验耗时和每份有效成果的成本。模型实验预先冻结任务、资料快照、工具权限、协议参数和预算，保留独立题与实际调用记录。投资效果另行按事前登记的期限和基准前向评估；离线样例验证计算与边界，不能用来推断收益能力。

## 6. 下一份专项规格应先决定什么

先固定公司判断、机会比较、持仓、方案和复盘之间最少需要互相引用的版本及字段，再选取上述多标的任务走通首次研究和一次更新。随后明确首批投资产品和价格、分红、汇率的数据覆盖，画像最小字段与部分账户降级方式，仓位区间的确定性方法及适用范围，最后明确真实流水来源和收益对账口径。FM 入口、供应商、商业价格、公开市场范围和交付日期保留为后续决策。
